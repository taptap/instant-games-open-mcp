# 序列帧动画：AI 使用说明

仅在用户主动询问或要求使用序列帧动画制作功能时，按下面的步骤打开现有界面；不主动推荐或发起生成。

## 打开并添加模板

角色模型模板包含真实生成的猫咪角色参考图；添加后的多视图与模型仍待生成，
保留原有多视图审核确认流程，不把角色图片标为已完成的3D模型，也不自动提交生成。

添加模板打开全屏模板库，可按道具与种植、角色与动画、UI设计、3D模型、我的模板筛选，
搜索名称或用途。条目尺寸统一，展示一张效果图或两张参考/结果图、说明与卡片数量；
预览来自实际示例，添加仍只创建独立副本，不自动生成。模板库关闭不改变画布。
动画在悬停整张模板卡片或键盘聚焦卡片内控件时播放，离开卡片且失焦后停止。
角色模型模板在列表内直接渲染随包提供的真实模型结果，支持拖拽旋转；不是角色参考图片。
模型示例仅用于只读预览，添加后仍按角色图、多视图确认、生模流程执行，不继承示例任务身份。
静态预览最长边768像素，按需加载；slot=0/1使用独立v3缓存，旧封面不复用。
模板素材或预览选择更新须增加revision，避免继续命中旧缓存。

自定义模板可从「⋯ → 导出 ZIP」分享，模板库「导入 ZIP」将其作为新模板保存到当前项目。
templateArchive.ts 使用 template.json 与 media/ 文件打包，按内容去重；导入通过原有素材
校验和模板保存接口写入，重新映射引用路径并保留结果的新旧状态。限制包体和展开总量
128 MiB，校验文件路径、类型和哈希，失败清理本次已写素材。Skill 只保留名称，不自动安装。

首尾帧变身预设不新增卡片，在原视频参数面板的图片引用区选择首帧、尾帧并排预览。
两张必填；移除首帧不会把尾帧变为首帧，缺图禁用生成；更换图片文件复用图片卡原有入口。
videoInputMode=first_last_frame 仅标记固定输入约束，frame-first/frame-last 连线保存角色，
来源仍只存 edges。保存/模板复制保留角色；UI、CLI 和服务端提交校验数量、顺序和模式。
修改引用保留旧视频和下游结果并标为待处理；未知任务先查询，不自动重提。
内置示例素材沿用已有版本，不代表用新提示词重新生成过；旧实例不自动改写。

1. 使用当前客户端已配置的 Maker CLI 打开控制台：

   ```sh
   taptap-maker console open --target-dir "<当前游戏的绝对路径>" --json
   ```

   命令沿用当前 Maker 启动入口，不临时安装其他版本。若不知道游戏目录，省略 `--target-dir`，让用户在控制台选择项目，不猜测目录。

2. 在控制台切换到「序列帧动画」栏目。
3. 点击「添加模板」，选择预设「序列帧动画」并添加，即可创建图片 → 视频 → 抽帧 → 序列帧动画的工作流。

有浏览器操作能力时，AI 可完成以上点击；否则打开控制台并告知用户点击位置，不宣称已添加模板。

到这里即可交给用户体验。打开界面、添加模板不需要构建或提交游戏；生成图片、视频会消耗积分，未经用户明确要求不要点击生成或启动队列。

图片已交付但画布本地导入失败时，使用「重试本地导入」恢复同一条记录，不重新调用付费生成；
二合图标也遵循此规则。未取得本地图片且执行结果不明时，先核实原结果，不允许通过重试重新扣费。
只有明确未执行的图片请求允许「重新生成（消耗积分）」，不自动重试。

视频不设本地固定冷却时间，能否提交由 Maker 服务判断。卡片「停止等待」或分组队列「停止」
会结束本地视频等待、暂停后续步骤，不取消远端任务，也不会自动重新付费生成。请求长时间未返回
时同样会释放本地等待。原 taskId 和结果保留在日志栏展开后的「视频历史」中，提交后 6 小时内
可查询取回；该期限仅为本地策略。主动重新生成可能重复扣费，请先核实原任务。

## 静态素材模板

「道具生成 · 风格图→图集→游戏资产」包含三张卡，没有便签：

1. 游戏风格图：林间炼金工坊完整游戏场景，包含森林、建筑、人物、道具及采集→炼制→售卖的玩法。
   这是游戏画面，不是角色立绘；必须保留场景、地面和背景。
2. 道具图集：普通图片卡，根据游戏画面的风格与内容生成 4 列 × 3 行的 12 件道具。
   第一行为药剂，第二行为采集材料，第三行为炼金工具；图集复用本地抠背景处理。
3. 游戏资产：卡面只展示独立透明 PNG；右上角「⋯ → 下载素材（PNG ZIP）」一次下载 12 张素材。
   ZIP 根目录只有 item_001.png～item_012.png，不包含动画配置或说明便签。

两张示例图片均通过 Maker 的 GPT 图片模型真实生成。道具透明背景是后处理结果，
不是模型原生 Alpha；玻璃内部保留原始高光，不是物理透明材质。

添加模板只复制已保存的素材、提示词和参数，不触发生图，也不携带历史 taskId 或 attemptId。
此道具预设添加后直接展示并可下载真实示例；修改风格图或图集后，下游才标记为待处理。
修改或替换首图后，调整图集提示词中的排列方式、完整道具清单和统一形状，再明确确认生成。
已有参考时生成整张图集只需一次生图；示例实际参考了包含场景与背景的完整游戏画面。
模板中的画布参考仅通过连线读取，不另存同一首图的固定路径，避免换图后继续混入旧参考。
新结果仍需检查风格、数量、网格、主体大小和边缘，再通过已有本地去背景入口处理。
模板沿用已有下游待处理确认规则，不自动生图、抠图、解析或付费重试。
本示例风格图为 2048×1152；图集生成结果为 2304×1536，未严格遵循请求的 4:3。
检查网格后，仅裁掉底部 36 行全透明留白，使图集成为 2304×1500、每格 576×500，
保留全部物品像素且边界不穿过主体。解析按实际尺寸进行，不将模型尺寸描述当作真实尺寸。

未逐项真实生成并检查效果的素材模板不进入内置列表；模板增加只修改数据与素材，
不借此新增生成模式、PSD 图层解析、透明视频、日夜天气能力或工作流引擎。

### 种植生长模板

「种植生长 · 作物→状态图集→游戏资产」使用三张现有卡片：

1. 作物参考：单个成熟番茄的透明物品图，用于确定物种、果实形状与美术风格，不是游戏场景。
2. 生长图集：根据参考图生成播种、幼苗、开花、结果、枯萎五阶段，按 5 列 × 1 行排列。
3. 游戏资产：五张真实透明 PNG，右上角「⋯ → 下载素材（PNG ZIP）」打包下载。
   item_001.png～item_005.png 对应上述阶段。保留相同画幅与底部落点，幼苗不放大到成熟株大小；
   游戏按生长状态切换图片，而不是将它们当连续动画播放。

番茄参考和图集均通过 Maker GPT 模型真实生成，再做本地抠背景与落点检查。
示例图集还离线整理了模型不等距的留白，并保护被抠图误删的果实高光；没有重绘或缩放植株。
最终图集为 2560×800，五张单图均为 512×800，土块底部落点为第 721 行（从 1 计数）。
该整理是本次示例制作步骤，不是画布的自动对齐能力。
模板中的提示词先判断物种：果菜五阶段，叶菜/根菜通常四阶段（播种、幼苗、可采收成熟、枯萎），
真菌四阶段（菌丝培养基、原基幼菇、成熟子实体、衰败），不强加种子或开花。
这属于提示词规则，不是已验证的自动植物识别或精确生物学模拟；本版实际验收的作物是番茄。

替换首图并确认生成后，先核对物种、阶段数量和顺序，再抠背景、解析。
解析窗口沿用已保存的五列参数；若新结果为四阶段，必须手动改成 4 列 × 1 行并检查网格。
生成的株型、间距和落点可能漂移，不保证每次无需整理；不对不规则结果强行裁切，
不增加自动识别格数、语义分割或付费重试。添加内置示例即可预览和下载，替换上游才标记下游待处理。

### UI 组件提取模板

模板的可选 skills 保存 Skill 名称，实例分组 templateSkills 保留添加时的关联；CLI templates/inspect 暴露关联，Agent 执行前读取对应 Skill。模板列表的阅读链接由 Store 端口提供，打开控制台文档阅读器，不启动 AI 或生成任务。用户模板及关联信息只在项目本地保存。

旧「UI组件提取 · 设计稿→组件图集→游戏资产」已从模板菜单移除，历史实例仍可使用。新的完整 UI 流程由 maker-ui-workflow Skill 引导，复用现有分层拆图模板和 UI 编辑器。以下为旧实例兼容说明：

1. 游戏 UI 参考：完整的花园商店界面，有背景、商品布局、资源栏及操作按钮，不是素材拼贴。
2. UI 组件图集：以参考图真实组件为依据，重绘为 4 列 × 3 行；不把整屏截图当作单个组件。
3. 游戏资产：12 张已抠背景的独立 PNG；右上角「⋯ → 下载素材（PNG ZIP）」打包下载。

从左到右、从上到下，item_001～item_012 分别为：主面板、标题丝带、主按钮、次按钮、
关闭按钮、空心头像框、商品槽、资源条、金币、蓝宝石、星标、返回按钮。
动态标题、按钮文字、数量和价格不烘焙进底图；关闭 X 与返回箭头保留为按钮图形。
头像框中心透明，面板和商品槽的奶油色内底保留不挖空。游戏按文件引用并另设文字和交互；
不包含字体、点击区域、响应式布局或九宫格拉伸配置，不应把整套组件作为动画播放。

参考界面和组件图集均通过 Maker GPT 生图能力真实生成。参考图实际为 1536×2304，保留背景；
模型图集实际为 2304×1536，洋红背景用现有本地抠背景算法清除（全图、自动颜色、容差65、
边缘过渡80、去溢色1）。模型的排列未严格落在等距网格内，本示例离线整理透明留白后成为
2560×1728；没有缩放或重绘组件，再通过画布实际解析生成 12 张 640×576 PNG 并验证 ZIP。
离线整理不是新增画布自动对齐或语义分割能力。

这是参考重绘，不是原稿无损拆层：示例主面板比例、标题及头像框装饰有重绘偏差；
遮挡内容由模型补全，不能保证任意 UI 设计稿精确还原。替换参考后先检查实际组件清单、
数量、轮廓、文字清理及网格，再抠背景并解析；不足12项时不虚构填格，需同步调整提示词与解析行列。
纯色背景须避开组件颜色，检查空心区域与高光；不规则排布不能直接强行网格裁切。
添加模板仅复制已保存示例，不调用付费生成；无便签、任务身份或新增常驻按钮。

### NPC 批量生成模板

「NPC批量生成 · 角色参考→职业图集→游戏资产」沿用三张内容卡，不新增卡片或批量任务界面：

1. 角色风格参考：一位完整的小镇邮差，已抠为透明背景；这里需要的是角色参考，不是道具模板的游戏场景图。
2. NPC 图集：参考画风，生成 4 列 × 2 行、共 8 位不同职业的完整角色；统一绘画媒介、视角、光照、描边与材质风格，用年龄、脸型、体型、服装及职业道具区分身份，不做同一人的换装列表。
3. 游戏资产：8 张独立透明 PNG；右上角「⋯ → 下载素材（PNG ZIP）」打包下载，卡面不常驻操作按钮。

本例从左到右、从上到下，item_001～item_008 对应铁匠、面包师、草药师、城镇守卫、
渔夫、图书管理员、旅行商人、旅店老板娘。邮差只作为画风参考，不重复占用八个职业名额。
参考与图集均通过现有 Maker GPT 生图能力生成，使用现有纯色抠背景算法处理；
本例选择八人是为给完整身体与随身道具留足空间，不是新增人数限制。
参考原图为 1536×2304，图集原图为 2304×1536。示例抠图使用自动颜色、全图处理、
容差65、边缘过渡40和去溢色1；原图守卫脚部跨过等分中线，离线只调整透明留白与脚底对齐，
未缩放人物，整理为 2560×1728 后按 4×2 解析成 640×864 PNG。
这不是画布新增的自动排版能力；色键抠图对发丝、细线及背景染色仍需在实际游戏背景上复查。
添加模板只导入完成的示例，不自动付费生成，也不保存原任务身份。

换参考时先修改图集提示词中的世界观和职业清单，沿用新图的比例、画法、视角与时代，
不要照搬本例服饰；人数变化必须同步修改图集解析的行列数。生成后先检查不同角色的辨识度、
头脚和道具完整性、相邻格留白及抠图边缘，再解析。模型不保证每次精确等距排列，
跨格时先修整或调整解析参数，不能直接裁断人物。它交付静态立绘，不生成数值属性、
对话、行为逻辑、骨骼、方向或动作动画，也不保证不同身高的游戏世界尺度自动统一。

### 二合图标生成模板

「二合图标生成 · 风格参考→升级图集→游戏资产」仍为三张卡：风格参考、升级图集、独立PNG。
升级图集沿用图片卡，仅以可选 mergeIcons 设置标识专用模式，不增加新节点类型、工作流引擎或MCP工具。
选中中间图片卡，使用「快速编辑 → 编辑升级阶段」；待更新卡也可从「调整参数」进入。
支持1～3个图标系列、每系列2～33阶段，每个阶段可填60字描述，留空由模型设计；补充要求最多400字。
数量缩小后，同系列暂时隐藏的高等级描述仍保留，调大可恢复；取消不改变已保存设置。
超过8阶段提示密度风险：一张图包含更多图标会降低单格像素，33阶段是参数范围，不是质量保证。

设置与实际生成记录分开保存：修改数量或描述不改写旧图片与旧提示词证据，图集及下游资产标为待更新。
当前设置编译成可查看的完整提示词，不能另写一份冲突的自由提示词；明确点击生成才提交。
需要有效风格参考；结果未知不重提。新图成功后原位更新，失败保留旧图与新设置。
更新设置后不能直接对旧图抠背景或按新数量拆图。已完成图集的本地抠图、编辑也原位保存，保留阶段设置。
图集解析默认列数等于阶段数、行数等于系列数；实际模型不一定严格对齐，仍需核对每格完整性。
按系列逐行、每行从Lv.1到最高级导出；图中不烘焙等级文字。ZIP沿用item_001等顺序文件名，
游戏自行映射系列与等级，不附带二合玩法、升级数值或交互逻辑。下载仍在游戏资产卡「⋯」菜单。

真实示例：面包篮、蓝色工具箱、藏宝箱各5阶段。参考图与图集均通过Maker GPT生成；
原图集为2048×1152，现有色键抠图使用自动颜色、全图、容差65、边缘过渡40、去溢色1。
模型首行末两格超出等分边界，本示例只离线整理透明留白，不缩放重绘，整理为2400×1296，
通过实际解析与ZIP下载得到15张480×432透明PNG。这不代表新增自动排版或语义抠图能力。
新生成先使用「去纯色背景」检查细边与透明区域，再进入图集解析；若解析窗口提前打开，先关闭再处理。

CLI沿用update-nodes的mergeIcons字段提交完整设置（stageCount、instructions、series数组，
每项含name与stages描述数组），之后显式run；配置本身不会生图。复制和保存用户模板保留设置、移除任务身份。

### UI 风格裂变模板

「UI风格裂变 · 同一界面→三种风格」只复用图片卡和提示词，不增加卡片类型、表单或生图接口。
左侧一张目标参考，右侧三张完整设计稿都直接引用左侧，不把上一种风格当成下一种风格的来源。

- 温暖手绘：奶油纸张、木质边框、柔和草木色，适合休闲经营。
- 暗黑奇幻：黑金浮雕、皮革与石材，适合中世纪魔幻RPG。
- 科幻终端：深蓝全息、切角面板与细发光线，适合太空探索。

添加模板即看到真实生成的每日签到原图和三张变体，均为2048×1152；不会自动付费生成。
通过原图片替换入口换入目标UI，三张下游保留旧结果并标为待更新。按需修改各卡「快速编辑」
中的风格提示词、画幅比例；使用已有分组队列依次生成，或只继续某一张下游。三种风格是三次
独立生图，失败停在当前任务，不自动重试。下载沿用每张图片卡的既有菜单。

提示词先识别当前参考的类型、格数、文字数字、按钮位置及状态，再改变配色、材质和装饰；
换成背包、宝箱或不同天数的签到图时不固定套用七天结构。生成后检查这些结构与语义是否保留，
尤其核对文字、奖励数量、选中和已领取状态。模型换肤不是像素级锁定，不保证任意复杂UI准确重绘。
此处保留完整背景与面板内底，不对整屏抠背景，也不附加图集解析或游戏资产卡。
产物用于设计比较和后续制作，不是PSD图层、切图组件、可点击界面或运行代码。

### 角色概念设计模板

「角色概念设计 · 角色参考→完整展示图」复用两张图片卡。输入一张面部清晰、服装和主要道具
可见的完整角色图；输出一张横版展示图：左侧动作立绘，右上正面、侧面、背面三视图，
右下微笑、大笑、愤怒、悲伤、惊讶、冷峻六种表情。提示词保持同一角色身份、服装和画风，
动作按参考角色和已有道具设计，不把森林法师的装备硬套给其它角色。

内置森林法师首图与展示图均真实生成，首图用现有去纯色背景处理为透明PNG，展示图保留
纸面背景和标签。添加后可直接查看和下载，不自动生图；替换首图后旧展示图保留并标为待更新。
通过原「快速编辑」改提示词和重新生成，通过图片卡原导出菜单下载完整展示图。
生成后逐项检查角色一致性、正侧背是否真实不同、表情能否区分以及主体是否裁切。
看不见的背面细节由模型补全，不能视为原稿精确还原；适用于提案和设计沟通。
动作立绘是静态图，不生成动画或3D模型。展示区域大小不同，不附加规则切图或游戏资产卡。

### 图集解析 / 导出单图

右键已就绪的图片卡 → 导出资源 → 图集解析 / 导出单图。此功能适用于规则排列的道具、
物品等静态图片，不需要专属拆分模型，也不识别物品语义。

1. 需要透明资源时，先使用已有抠背景功能；裁切本身不删除背景。
2. 设置列数和行数，必要时调整左右/上下边距与列/行间距（整数像素）。
3. 查看编号网格并确认每格物品完整、不跨格。修改参数后需重新确认。
4. 点击「生成游戏资产卡」：通过已有受控导入保存每张 PNG，全部成功后才创建或更新资产卡。
   卡片支持重载后预览和菜单下载，不常驻下载或重新解析按钮。需要再次解析时回到来源图集；
   来源删除不删除已经保存的素材。
   导入或保存失败保留原结果，来源在处理期间变化时停止，不会将素材写入其它画布。
5. 也可直接导出单图包（独立 PNG、index.json、README）或 Maker 静态图集包
   （spritesheet.png、spritesheet.json、README）。物品按从左到右、从上到下编号 item_001 起。

导出保留原像素、透明度与留白，不缩放、不旋转、不自动裁透明边，不生成动画配置。
Maker 可直接通过 UI.Sprite 的 frame 属性引用静态图集区域，不必物理拆分；
独立 PNG 可用于 UI.Panel 的 backgroundImage。包内说明给出 assets/image/items/ 和 Lua 路径。
直接导出仅读取图片快照，不修改画布。生成资产卡写入独立图片和资产列表，但不发生成请求，
不新增服务端接口或新的模型能力。
支持每边最多 4096 像素、最多 120 格、ZIP 最多 128 MiB。不规则排布、跨格物品或语义拆分
不在此版本范围内，不能仅靠网格解析修复模型生成的内容错误。

## Canvas CLI（首版）

AI 可以通过当前安装的 Maker CLI 操作已打开的画布，无需浏览器自动点击，不新增 MCP tool。
所有命令绑定明确的项目绝对路径；不要使用其它项目、默认 cwd 或直接修改 .maker 内的 JSON。

链路：AI → canvas CLI → 本机控制台转发 → 画布页面现有操作 → Store 保存。
编辑、生成、抽帧需要页面保持打开；列表和已保存快照不需要页面。后台浏览器被系统暂停时，
命令可能无法及时执行；回到画布页后重新查询，不自动重发生成。

### 使用顺序

1. 查询 capabilities、list、templates、pages。pages 返回页面 ID、当前画布 ID、revision 和打开页面的 URL。
2. 用 inspect 读取实时卡片、连线、队列和阻塞原因。多个页面时明确选 page-id，不猜测用户所在页面。
3. 提交编辑时带上该快照的 revision；参数建议写入 UTF-8 JSON 文件，避免 Windows 命令行转义问题。
4. 命令立即返回操作 id，再用 wait 等待或 status 查询。wait 默认等 30 秒，最多 60 秒；超时返回当前状态，
   不取消或重提任务。succeeded 表示本次命令完成；query 成功不代表视频已完成，要看返回的卡片状态。
   图集预览完成返回 result.status=waiting_for_confirmation，表示等候网格核对，不是最终组件已生成。

   taptap-maker canvas capabilities
   taptap-maker canvas pages --target-dir "<项目绝对路径>"
   taptap-maker canvas templates --target-dir "<项目绝对路径>"
   taptap-maker canvas inspect --target-dir "<项目绝对路径>" --page-id <页面ID> --canvas-id <画布ID>
   taptap-maker canvas wait --target-dir "<项目绝对路径>" --operation-id <操作ID>
   taptap-maker canvas update-nodes --target-dir "<项目绝对路径>" --page-id <页面ID> --canvas-id <画布ID> --revision <版本> --input-file "<参数JSON路径>"

离线于页面的只读查询：inspect --saved --canvas-id <画布ID>，返回 source=saved，不包含实时任务状态。
首次没有页面时，打开 pages 返回的 URL，或按上面的控制台步骤进入序列帧动画。

### 支持的操作

| 命令                             | input JSON                                                 | 说明                                                                        |
| -------------------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------- |
| create / rename                  | {"title":"新画布"}                                         | 新建并切换 / 重命名当前画布                                                 |
| open                             | {"id":"目标画布ID"}                                        | 从当前画布安全切换                                                          |
| add-template                     | {"id":"模板ID"}                                            | 添加内置或用户模板的独立副本，不修改模板库                                  |
| add-node                         | {"type":"image"}                                           | 新建 image、video、note；sequence/animation 另传 sourceId，复用现有派生流程 |
| import                           | {"title":"角色参考"}                                       | 另传 --file 本地绝对路径，导入为新卡片，不覆盖已有卡片                      |
| set-references                   | {"id":"目标ID","sourceIds":["图片ID"],"includeSelf":false} | 有序替换全部图片参考；[] 清空，includeSelf 仅图片卡可用                     |
| export                           | {"id":"结果ID","format":"atlas","loop":true}               | 导出已有结果；另传 --output-dir 已存在的绝对目录可直接保存                  |
| update-nodes                     | {"nodes":[{"id":"卡片ID","prompt":"完整猫咪，站立"}]}      | 批量校验后修改，不自动生成                                                  |
| delete-nodes / duplicate / group | {"ids":["卡片ID"]}                                         | 删除 / 复制 / 分组；删除分组本身不删除成员                                  |
| connect                          | {"from":"图片ID","to":"视频输入卡ID"}                      | 已保存图片连接到尚未生成的视频输入卡                                        |
| disconnect                       | {"edgeId":"连线ID"}                                        | 只移除图片参考线，不拆断序列帧/动画来源                                     |
| run                              | {"id":"卡片或分组ID"}                                      | 单卡执行或运行分组剩余步骤；已完成模板卡先修改参数                          |
| stop                             | {"id":"视频卡或分组ID"}                                    | 停止本地视频等待或后续队列，不取消远端任务                                  |
| query                            | {"id":"视频卡ID"}                                          | 查询原视频任务，不发起新生成；历史面板仍由人工操作                          |

update-nodes 支持 title、便签 text、单卡位置 x/y、prompt、parameters、sequenceSettings。
generation 的任务标识、结果路径、来源快照不允许写入。空图片和视频卡使用生成草稿保存输入；
已有素材保留，模板修改只标记待处理，不覆盖下游结果。

图片 parameters：model=auto/gpt/nanobanana，resolution=1K/2K，aspectRatio=1:1/16:9/9:16/4:3/3:4。
视频 parameters：model=2.0/2.5，resolution=720p/480p，duration=4～8，ratio=adaptive/16:9/9:16/1:1，
mode=first_frame/first_last_frame/multi_modal_reference。Seedance 2.5 的首帧/首尾帧模式必须使用
ratio=adaptive。参考图数量和来源仍按原界面校验。

抽帧开放 start/end（秒）、fps（1～30）、width/height（1～2048）、fit（contain/cover/stretch）、
pixel、cutout、cutoutMode（connected/chroma）、backgroundColor（#RRGGBB）、tolerance（0～255）。
最多 120 帧，还受原处理器的像素及图集容量约束。run 复用模板抽帧流程，自动去重阶段保留全部帧，
不替用户删帧。画笔、蒙版、逐帧修图、人工去重确认和模板库保存/替换暂不开放 CLI，仍可在界面使用。

### 已有素材到游戏资源

1. import --file "<本地绝对路径>"：PNG/JPEG/WebP 图片最多20 MiB，MP4/MOV/WebM 视频最多100 MiB。
   返回新增卡片 selectedIds。CLI 读取文件，控制台复用受控导入，页面解码成功后才添加卡片。
   上传成功但后续操作被拒绝时，素材可能已在项目内，但不会添加到其它画布；不要直接修改素材路径。
2. 图片用途：set-references 指定目标卡和有序图片ID；默认不引用目标自身。
   图片 sourceIds=[] 且 includeSelf=false 为纯文本生成；视频清空后必须补参考图才能生成。
   引用选择随画布保存，替换输入保留旧生成结果、只标记待处理，不扣费、不自动生成。
   旧版固定 templateFlow 的视频来源不允许通过 CLI 更换，需从添加模板创建新版副本；不会半途改写旧流程。
3. 视频用途：add-node 的 input 传 {"type":"sequence","sourceId":"视频卡ID"}，再修改抽帧参数并 run。
   已保存序列帧可用 {"type":"animation","sourceId":"序列帧ID"} 创建动画，不自动打开编辑器。
4. export 的 format：图片 png/jpg，视频 video（原字节），序列帧或动画 atlas/frames（Maker ZIP）。
   两种ZIP均复用界面导出格式与命名，导出不会触发生成或修改游戏代码。
   --output-dir 由 CLI 在本机解析，控制台不会接收任意输出路径。同名文件增加序号，绝不覆盖已有文件。

   taptap-maker canvas import --target-dir "<项目>" --page-id <页面> --canvas-id <画布> --revision <版本> --file "<图片或视频>"
   taptap-maker canvas export --target-dir "<项目>" --page-id <页面> --canvas-id <画布> --revision <版本> --input-file "<导出参数JSON>" --output-dir "<目录>"
   taptap-maker canvas download --target-dir "<项目>" --operation-id <导出操作ID> --output-dir "<目录>"

带 --output-dir 的 export 最多等待60秒；尚未完成时保留原操作ID，用 status/wait 查询，再 download。
不带 --output-dir 则与其它命令一样立即返回操作ID。下载成功返回 outputPath；只有该字段才证明已写到本地。
导出临时字节按操作隔离、总量最多128 MiB、10分钟过期；成功下载后释放，写入失败可再次 download。
缓存过期或控制台重启后重新 export 即可，不需要重新生成。import 的 request-id 已存在时拒绝再次上传，
请查询原操作，避免为同一导入重复创建素材。

### 图集解析为独立 PNG

对模板中的 image-assets（游戏资产）卡使用以下步骤；卡片 id 可通过 inspect 取得。
CLI 与界面共用网格预览绘制、裁切和保存逻辑，CLI 预览不打开阻塞弹窗、不创建最终组件。

1. 执行 preview-image-assets，input 为
   {"id":"游戏资产卡ID","grid":{"columns":4,"rows":3,"marginX":0,"marginY":0,"gapX":0,"gapY":0}}。
   grid 可省略，沿用图集已有设置或 4×3 默认值；行列为正整数、最多 120 格，边距/间距为非负整数像素。
2. 用 wait/status 取得结果：status=waiting_for_confirmation、reviewId、revision、regions 和
   preview.dataUrl（PNG data URI）。将 data URI 解码为本地 PNG 并实际查看，逐格核对主体完整与透明度。
   预览只画网格，不判断物品语义。跨格时调整网格参数或原图后重新预览，不能直接确认。
3. 核对后显式调用 confirm-image-assets，携带当前 --revision，input 为
   {"id":"游戏资产卡ID","reviewId":"本次预览标识"}。确认只使用已预览的图片字节和网格；
   新预览、画布版本/来源变化、页面重载及一次确认尝试都会使旧标识失效，失败后先检查再重新预览。
4. 确认成功返回 status=completed 和 items（名称、路径、尺寸）。重新 inspect 后，执行
   export，input 为 {"id":"游戏资产卡ID","format":"images"}，用 --output-dir 或 download 取得 PNG ZIP。

run 游戏资产卡等同于请求默认网格预览，不自动确认。含游戏资产卡的分组不能通过 CLI 一次跑完，
请分步执行上游图片，再预览、核对和确认；普通鼠标操作仍使用原解析弹窗。
等待确认可在实时 inspect 的 state.imageAssets 中查询；不写入画布文件，刷新后重新预览即可。
规则网格切图不会自动纠偏、抠背景或语义命名；生成图片不满足网格是需要检查的输出质量问题。

### 更小的状态查询

capabilities 返回参数类型、选项、范围和重要组合限制。inspect 的 input 可传 {"id":"卡片或分组ID"}，
仅返回目标、组内卡片和直接上游；队列信息仍是关联分组整体状态，不把局部列表误当完整画布。
inspect --saved --canvas-id <画布ID> --id <卡片或分组ID> 可筛选已保存快照。
guidance 只是当前快照的操作提示，不保证可执行；source=saved 不代表正在运行的页面状态。

### 角色 3D 模型模板

在“添加模板”选择“角色模型 · 多视图确认”。流程为：

    角色图片（生成或导入并确认外观）
      → 多视图（展示上游返回的全部视图，不写死三张）
      → 人工确认全部视图 → 3D 模型（项目本地模型包）

角色图复用图片卡；双足角色建议正面完整全身、A 姿势、四肢分离、无遮挡、纯色背景。
四足动物和道具应按实际对象改角色提示词，不机械套用 A 姿势。画布只把确认的图片传给生模服务，
不额外拼接隐藏提示词。多视图卡默认 balanced，可改 fast（草稿）或 high_quality；
质量应在生成多视图前选好，修改后旧预览失效，需要新流程或重新生成视图。

上游 create_3d_asset 的完整协议是 start / query / get_options / continue / post_process。
本模板固定使用 reviewed 图片流程，不走 direct，不自动确认预览；远端可能返回四个方向，
全部下载成功后才开放确认。后台支持面数、贴图/PBR 等 options，但受服务端阶段及质量策略限制；
本版只开放三个质量档位，不写死高级参数。绑骨、贴图重做、重拓扑、格式转换仍使用原 Maker 工具，
不加入画布首版。模型交付后，点击“查看模型 · 旋转预览”打开详情弹窗，可拖拽旋转、滚轮缩放及复位。
预览直接读取交付包内的 UMD2 MDL、prefab/材质 UUID 与基础色贴图，不调用转换或付费接口；
仅显示静态外观，不播放骨骼动画，也不保证与引擎 PBR 光照一致。缺失依赖、不支持的格式或无 WebGL2 时
明确提示，可继续导出原模型包。关闭弹窗释放加载请求、纹理与 WebGL 资源，卡片不常驻 3D 渲染器。

CLI 与界面复用同一入口：

1. add-template 使用模板 ID 7e1cb6ad-732f-4dc3-a951-000000000004。
2. 编辑/生成角色图片，或使用 import 导入图片，再 add-node 创建 model-views（sourceId=图片ID）
   和 model（sourceId=多视图卡ID）。模型卡不能没有上游，也不接受任意结果路径写入。
3. update-nodes 可设置多视图卡的 modelQuality：fast / balanced / high_quality。
4. 确认角色图后，对多视图卡执行 run --allow-paid。inspect 的 state.model 返回状态、全部预览路径、
   assetId/taskId 及 reviewId。query 查询原上游任务，不发起新的生成。
5. **展示全部预览并取得用户明确批准后**，执行 confirm-model --allow-paid，input 为
   {"id":"模型卡ID","reviewId":"当前预览令牌"}。通用 run 或分组队列不会跳过确认。
6. query 直至 state.model.status=completed；以 modelPath 为实际本地交付入口。
   preview-model 的 input 为 {"id":"模型卡ID"}，只打开只读预览弹窗，不修改画布、不扣费；
   返回 opened 只表示弹窗打开，加载结果需查看弹窗状态，不等同于模型视觉验收通过。
   多视图卡使用四宫格预览；模型卡自动读取真实模型、显示固定视角缩略图，点击后打开旋转预览。
   质量、任务查询、路径复制和预览重试收在卡片右上角菜单。缩略图失败不影响已有模型和导出，
   “重试预览”只重新读取本地资源，不重新生成或扣费。
   右键模型卡导出，或 export 的 format=model，可下载含模型、材质、贴图原相对路径的 ZIP。
   带 --output-dir 即保存到本地目录；不重命名包内依赖文件。最多121个资源文件、128 MiB，
   超限时明确提示从项目 assets/model 目录复制，不导出不完整模型包。

canvas models --target-dir "<项目绝对路径>" --canvas-id <画布ID> 返回持久任务记录，
无需页面；这是本地记录，不代表已刷新远端状态。新建、执行和确认仍需要打开画布页。

原型图或质量变化后，旧预览不能确认，旧产物保留；结果未知或生成中不能再次提交。
任务 ID 在素材下载前落盘，刷新不自动恢复付费生成。停止等待只释放页面，不取消远端；
原请求还在执行时先“刷新本地状态”，请求结束后再“查询原任务”。模型查询不沿用视频6小时期限。
单卡复制不复制模型依赖或任务；要创建独立模型流程，请添加模板或把完整流程另存用户模板。

### 安全与恢复

- 生图、生视频或分组 run 必须先取得用户授权，再显式传 --allow-paid；修改参数、添加模板不会扣费。
- 页面有未保存修改、参数面板、编辑器草稿或执行中任务时，拒绝冲突操作，不丢弃人工编辑。
- 关闭生成面板不代表提交人工参数草稿。仍有草稿时，先手动完成生成，或刷新页面明确放弃，再交给 AI。
- 可传 --request-id 标识同一次操作；同一会话重复请求返回原操作，不重复执行。不同参数不能共用 ID。
- 保存失败时修改可能已在页面，保留页面手动保存；不要再次添加模板或重新生成。
- 页面刷新、断开或控制台重启后，原命令不自动重放。unknown 表示结果待确认，不是重试许可。
- 操作记录只在本次控制台会话内存在，不是持久任务系统。生成 taskId 仍由视频历史持久保存。
- query 先刷新本地生成记录，可取回停止等待后才返回的 taskId；尚未返回 ID 时稍后再查，不能重提生成。
- 保留最近 20 次完整结果，更早记录标记 resultExpired；需要详情时重新 inspect。
  每次控制台会话最多接收 1000 条命令，达到上限后完成现有任务再重启控制台。
- 画布打开、CLI 状态成功或抽帧成功不等于视觉验收通过；朝向、完整构图、抠图质量仍需看图确认。
