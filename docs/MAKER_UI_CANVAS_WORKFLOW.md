# 游戏 UI 制作：画布功能流程说明

本文面向产品、美术和研发，说明现有「游戏UI制作」模板如何把设计稿处理成独立 PNG 资源包，
包括操作过程、分层规则、数据传递、提示词和完成标准。

第 1～7 节和提示词附录描述「关闭识图」的基线流程，供有/无识图对比。
画布添加模板默认关闭识图，CLI run 默认开启并先完成识图；无识图对比显式传 recognition:false。AI／CLI 开启时先去文字，再由当前对话 AI 识别去文字图并通过 update-nodes 写入元素清单；美术字支线仍引用原稿，
程序按坐标标框，拆图提示词和网格按清单生成。
去文字卡旁的便签展示已选清单，该卡的「识图：开/关 · 对比」可查看多个模型的结果、下载清单、选择结果。
两种模式都沿用原队列，终点均为 PNG 资源卡。接口配置与详细操作见
[元素识图与对比测试](MAKER_UI_WORKFLOW.md#元素识图与对比测试)。

## 1. 功能目标与边界

用户在新画布中添加「游戏UI制作」模板，替换原设计稿，再运行分组剩余流程。
系统沿现有连线自动处理图片、生成图集、抠背景和裁切，最后得到内容已准备好的资源卡。

- 输入：一张完整的游戏 UI 设计稿。
- 输出：分好类别的图片图集，以及可预览、下载的独立 PNG 资源包卡片。
- 画布流程止于资源包；资源加入项目、生成 meta、组装 UI.json、打开 UI 编辑器由后续 CLI 或 Skill 处理。
- 原设计稿与过程图保留，便于对照。新切图保存在当前项目的画布资源目录，不自动进入游戏正式资源目录。
- 模板示例用于展示效果。新添加的模板只有输入示例就绪，下游步骤为待处理，不能把示例当作本次结果。

当前操作入口名为「完成剩余流程」。一次确认后自动执行；图片生成会消耗积分，页面需要保持打开。

## 2. 三个大步骤总览

为便于讲解，本文按业务把流程分为三段。第一段包含画布中的「原设计稿」和「去文字设计稿」卡片；
第二段对应分类标注与背景准备；第三段对应所有图集和资源包。

| 大步骤             | 目的                                             | 主要输出                                 |
| ------------------ | ------------------------------------------------ | ---------------------------------------- |
| ① 原稿准备与去文字 | 保留完整原稿，得到适合提取底板和图标的去字参考图 | 原设计稿、去文字设计稿                   |
| ② 分类识别与标注   | 分别识别按钮、Icon、美术字，并准备背景层         | B 编号图、I 编号图、T 编号图、背景准备图 |
| ③ 分层提取与资源包 | 按分类生成规则图集，抠底并裁成独立 PNG           | 9 类图集及对应资源卡                     |

实际连线如下。四条分类分支在业务上独立，当前由同一条串行队列按依赖顺序执行。

```text
原设计稿
├─ 去文字设计稿
│  ├─ 按钮标注 B → 页签／主操作／快捷入口／关闭底板 → 各自 PNG 资源包
│  ├─ Icon 标注 I → Icon 图集 → PNG 资源包
│  └─ 背景准备 → 独立背景框／标题底板／完整主面板 → 各自 PNG 资源包
└─ 美术字标注 T → 美术字图集 → PNG 资源包
```

美术字必须引用原稿：去文字步骤已经删除美术字，不能再从去文字稿提取。

## 3. 第一步：原稿准备与去文字

### 操作与处理

1. 添加模板，在原设计稿卡片上使用「替换图片」，保留现有流程连线。
2. 保存后，下游按新输入处理；旧示例保留作预览，但显示待处理。
3. 去文字节点引用新原稿，移除普通文案、数字、按钮及页签小字、Icon 内小字和美术字体。
4. 尽量保留原构图、按钮形状、图标、底框、材质等非文字信息。

原设计稿仍是内容核对的依据。去文字稿是 AI 生成的中间结果，存在局部重绘或细节变化的可能，
不能将“生成成功”等同于像素级保真。普通文字后续通常由 UI Label 还原，美术字则走独立图片分支。

### 当前提示词

```text
精准去除所有普通文案、数字、按钮小字、页签小字、Icon 内小字及美术字体，保持原构图和非文字细节。
```

## 4. 第二步：分类识别与标注

### 4.1 按钮与页签

- 输入：去文字设计稿。
- 识别对象：按钮及可点击页签。
- 标注方式：在参考图上画框，为每个实例分配独立 B 编号，保留原位置。
- 分层要求：按钮底板与 Icon 分开；相似实例在识别时分别编号，不直接合并。
- 输出：按钮标注图片，供四类按钮提取分支参考。

### 4.2 Icon 与装饰小图

- 输入：去文字设计稿。
- 识别对象：独立 Icon、装备、道具和装饰小图。
- 标注方式：每个实例独立 I 编号，保留原位置。
- 排除对象：背景框、普通文字和按钮底板。
- 输出：Icon 标注图片。

### 4.3 背景准备

- 输入：去文字设计稿。
- 保留：主面板、分区底板、装饰框及其原位置。
- 移除：文字、Icon、按钮及按钮内图案，并修补移除后的区域。
- 输出：一张背景准备图，供标题底板、独立背景框、完整主面板三个分支提取。
- 当前没有为每个背景元素单独编号的要求。

### 4.4 美术字

- 输入：原设计稿。
- 识别对象：独立美术字及字效。
- 标注方式：用 T 编号标注字形边界，保留原文字与位置。
- 分层要求：不把后方木板、边框或按钮背景算进字形。
- 输出：美术字标注图片。

### 4.5 当前真正保存了哪些信息

| 信息                                           | 当前保存方式                           |
| ---------------------------------------------- | -------------------------------------- |
| B／I／T 编号、框选范围、图中位置               | 画在标注图片里                         |
| 标注图片                                       | 图片文件及画布卡片引用                 |
| 生成要求                                       | 卡片提示词                             |
| 输入关系                                       | 来源图片 ID、连线和来源版本快照        |
| 生成配置与结果                                 | 模型、分辨率、比例、任务记录、结果路径 |
| 每个元素的编号、类型、原图坐标、颜色、状态清单 | 尚未结构化保存                         |
| 元素编号与输出 PNG 的对应关系                  | 尚未自动建立                           |

卡片的 x、y、width、height 是画布上的展示位置与大小，不是设计稿内部元素的坐标。
当前识别节点调用的是图片生成能力，输出标注图，没有同时返回一份机器可读的元素清单。

## 5. 第三步：分层提取、抠底与资源包

### 5.1 AI 分离与图集生成

这一阶段不是直接按原稿坐标裁矩形。AI 参考上一阶段图片，移除无关内容、保留目标主体，
把同类素材重新排列成规则图集；随后本地程序才按网格裁切图集。

当前模板的预设数量如下。它们来自模板配置，不是根据新原稿自动识别得到的数量。

| 类别           | 输入         | 网格（列 × 行） | PNG 数量 | 核心分层要求                             |
| -------------- | ------------ | --------------- | -------- | ---------------------------------------- |
| 页签双状态     | 按钮标注图   | 5 × 2           | 10       | 上排默认、下排按下；移除 Icon 和文案     |
| 主操作双状态   | 按钮标注图   | 2 × 2           | 4        | 提取按钮底板，移除图标和文案             |
| 快捷入口双状态 | 按钮标注图   | 3 × 2           | 6        | 当前提示词要求移除 Icon 和普通文字       |
| 关闭底板双状态 | 按钮标注图   | 1 × 2           | 2        | 移除关闭叉号 Icon，只保留底板            |
| Icon 贴图      | Icon 标注图  | 4 × 4           | 16       | 完整独立图标，去除编号和底框             |
| 独立背景框     | 背景准备图   | 1 × 7           | 7        | 边框与内部填色一体，移除子框、网格和前景 |
| 标题底板       | 背景准备图   | 2 × 2           | 4        | 每格一条完整横向标题条，不带整块界面     |
| 完整主面板     | 背景准备图   | 1 × 1           | 1        | 外围轮廓与内底一体，移除内部独立分区     |
| 美术字         | 美术字标注图 | 1 × 2           | 2        | 只保留字形、描边和字效，不带后方底板     |
| 合计           |              |                 | 52       | 9 张资源包卡片                           |

默认与按下状态要求尺寸、主体位置和锚点一致。原稿未提供的按下态属于 AI 补生成，
需要视觉复核。当前页签提示词还允许不足 5 种时补充状态变体，Icon 提示词允许重复素材共用；
因此“格子已填满”并不能证明“原稿所有实例都已覆盖”。

### 5.2 提示词组织方式

分类提示词通常分四层：

1. 参考与目标：使用哪张参考图，本次提取哪一类素材。
2. 保留：主体、颜色、材质、轮廓，以及需要一体保留的边框和内底。
3. 移除：文字、Icon、编号、子框或其他不属于本层的内容。
4. 输出：行列数、素材数量、状态顺序、留白与背景要求。

“移除编号”指最终素材图片不要带 B／I／T 字样。理想情况下，编号仍应保存在素材元数据里；
当前尚未实现这一对应关系。附录给出当前模板的实际提示词原文。

### 5.3 两种抠图底色

生成 UI 图集前，对当前参考图片的配色采样，在以下两种背景中选择冲突较小的一种：

- 洋红：`#FF00FF`，RGB(255,0,255)。
- 绿色：`#00FF00`，RGB(0,255,0)。

选择是配色启发式，不是逐元素语义识别。红色、粉色较多时倾向绿色，绿色较多时倾向洋红；
它可以降低主体与底色冲突，不能保证所有同色主体、发光或半透明边缘都完全正确。

系统同步修改提示词中的背景约定，并把选择的底色记录到生成结果的 `cutoutColor`。
切图按结果记录的底色处理，不根据之后编辑过的提示词猜测。旧结果没有底色记录时使用洋红。

动态附加约定如下，其中名称、十六进制值及 RGB 会替换为同一种颜色：

```text
抠图底色约定：所有主体外背景和间隔均为平涂纯{底色名称} {HEX}，RGB({R},{G},{B})；无背景纹理、渐变、投影或底色反光。保留主体原有配色、描边和字效，不为避开底色改变主体颜色。
```

### 5.4 本地抠底与裁切

1. 读取图集，沿用资源卡保存的行列、边距和间距。
2. 游戏 UI 资源使用边界连通的去背景处理，尽量保留原有透明度和内部装饰。
3. 零边距、零间距网格可利用素材间的透明分隔调整切分位置，并平移越界主体，不缩放或切断主体。
4. 显式设置了边距或间距时，按保存参数裁切。
5. 检查空格、明显跨界、缺少可靠透明分隔和主体超过格子容量等情况。
6. 独立 PNG 写入 `.maker/canvases/<画布ID>/resources/`，资源卡保存后才计为完成。

当前资源列表记录图片路径、尺寸和网格顺序名称，如 `item_001`；这些名称不等于 B／I／T 编号。
上述检查验证切图结构与文件，不自动判断图片是不是原稿中的正确按钮或是否漏了某个元素。

## 6. 自动执行与容错

使用现有串行队列，以画布连线作为依赖关系，不按卡片名称或编号调度。

| 情况                             | 当前行为                                                     |
| -------------------------------- | ------------------------------------------------------------ |
| 正常完成一步                     | 保存结果后继续下一个可执行步骤                               |
| 某分支失败                       | 保留原因；依赖它的节点等待，独立分支继续                     |
| 确定的生图失败／图集排版无法切分 | 每个生图节点最多自动重生 2 次，排到其他可执行分支之后        |
| 图集排版重试                     | 补充当前数量、行列、完整主体、留白和底色要求                 |
| 生图请求等待超过 5 分钟          | 结束本地等待，保留原任务待核查，不将超时当作确定失败重新付费 |
| 相关读取或保存等待超过 60 秒     | 结束本地等待并显示错误                                       |
| 未知结果／本地下载失败           | 核查或恢复原结果，不自动重新付费生成                         |
| 画布保存失败                     | 暂停所有后续生成，保存成功后才能继续                         |
| 用户停止或关闭页面               | 不再自动接续；不等于取消远端任务，刷新不会自动恢复付费执行   |

同一页面继续保留已完成计数和重试次数。重新接续时先检查已有任务，符合恢复条件的已生成图片
复用原结果，不重复提交。自动重试目前针对执行失败与排版问题，不包括自动发现漏元素或配色错误。

## 7. 完成标准与当前限制

### 当前“流程完成”的含义

- 已配置节点执行结束，资源卡中的 PNG 已生成并保存。
- 文件存在、可读取，数量与配置网格一致。
- 基础切图检查通过。

### 仍需对照原稿复核的内容

- 原稿是否有元素未识别、被错误分类或未提取。
- 按钮颜色、形状、材质是否保持，是否把其他蓝色底板当成黄色按钮。
- 默认与按下态是否对齐，是否残留文字、编号或不属于当前层的图案。
- 透明边缘是否存在毛边、残色，主体是否变形或细节丢失。

当前不能将“9 张资源卡、52 张 PNG”作为完整覆盖任意设计稿的证明。
例如标注图里有 B32、B34、B36 三个黄色按钮，而主操作分支固定为两组双状态，
模型又可能选择其他按钮；即使输出 4 张可用 PNG，仍然没有覆盖这三个实例。

## 8. 清单模式与尚未完成的内容核对

业务目标：允许冗余切图，但原稿需要的元素不能静默遗漏。沿用现有队列与资源卡，补齐信息传递：

1. 已接入：识图模型输出编号、类别、原稿位置、外观描述、层级和可见状态，保存 JSON，便签和标框图从同一份数据生成。
2. 已接入：具体编号及要求传给拆图节点，提示词列出预期槽位，数量随清单确定；单类超过 120 格明确报错，尚不自动分批。
3. 尚待内容核对：模型不一定按预期槽位输出。当前不能把提示词中的槽位关系当成已经验证的 PNG 身份绑定。
4. 尚待内容核对：识别本身可能遗漏，生图也可能省略或混淆组件；需对照原稿和实际 PNG 复核，队列完成不代表语义覆盖验收通过。

只给文件改名或在提示词中加入“不能遗漏”不足以实现上述目标。
开启识图已补齐机器可读清单；关闭识图仍只依赖图片参考。自动语义核对尚未接入。

## 9. 提示词原文附录

以下为当前内置模板的分类与提取提示词。底色原文使用洋红，实际运行会按第 5.3 节同步替换。
排版失败时还可能附加当前行列和数量的纠正要求。不同画布里手工修改的提示词以该画布实际保存值为准。

### 9.1 ②-A 按钮标注

```text
参考与目标：以输入参考图为依据，完成按钮分析标注。
保留：在参考图上识别按钮及可点击页签；每个实例记录独立B编号并保留原位置。
移除：不要把Icon当作按钮底板，不把相似实例合并。
输出：原图上画框和编号；标注全部按钮，不拆图、不改布局。
```

### 9.2 ②-B Icon标注

```text
参考与目标：以输入参考图为依据，完成Icon分析标注。
保留：在参考图上识别全部独立Icon和装饰小图；每个实例记录独立I编号并保留原位置。
移除：不要把背景框、普通文字和按钮底板混入Icon。
输出：原图上画框和编号；相似实例也分别编号，不拆图、不改布局。
```

### 9.3 ②-C 背景准备 · 去除Icon与按钮

```text
参考与目标：以输入参考图为依据，完成背景分层准备。
保留：保留原稿主面板、分区底板和装饰框的原位置。
移除：移除文字、Icon、按钮及按钮内图案，修补遮挡区域。
输出：单张背景准备图，不移动剩余背景框。
```

### 9.4 ②-D 美术字体标注

```text
参考与目标：以输入参考图为依据，完成美术字体分析标注。
保留：识别原稿中独立美术字及字效，使用T编号标注字形边界。
移除：不把后方木板、框、按钮背景计入字形。
输出：保持原稿位置，只画美术字边界与编号，不抹掉原文。
```

### 9.5 ③ 页签双状态 · 10 PNG

```text
参考与目标：以输入参考图为依据，完成页签按钮双状态。
```
