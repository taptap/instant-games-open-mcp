# Maker UI 设计稿到游戏素材工作流

普通「游戏UI制作」使用固定分类提示词独立完成去文字、生图、切图与资源包，就绪的生图分支全部并发，每张完成后立即切图。
去文字设计稿保留完整布局，供按钮、图标、装备与人物提取；背景准备在去文字图上移除图标、按钮、人物与静态插画并补底，再提取主面板、分区底板、独立槽框和环境背景。美术字仍引用原稿。环境背景输出铺满原画幅的不透明图片，不能套用透明图集边距。
Bbox 是可选附加数据，识图失败不阻塞主流程，可从去文字卡手动重试；重试不重新生成已有素材。
普通模板失败时，卡片显示原因和「重试并继续」；分组可继续剩余流程，复用已完成上游。
Bbox 预排模板必须取得匹配的识图数据：去文字完成但 Bbox 缺失时，卡片显示「等待 Bbox 数据」，
下游可定位识图卡，识图卡可生成、重试或查询原请求。数据回填后提示自动消失，可继续原流程。
下文按 Bbox 分批、槽位绑定的说明适用于非可选识图流程与 Bbox 实验模板。

## 图集与 Bbox 的关联

识图结果随画布保存时自动归档；完整资源终点（或没有终点卡的模板分组）保存完成时，
同时归档分类 PNG、Bbox、bindings 及原稿/去文字参考图。官方合批模板与历史分类模板共用此保存链路。
位置为 `.maker/canvases/ui-archives/<画布ID>_<识图卡ID>/<版本>/`，复用已有本地隔离和忽略规则。
`bbox-<SHA256>` 为识图版本，`assets-<SHA256>` 为资源版本；相同内容幂等，新内容不覆盖旧目录。
名称仅作显示，UI 身份不依赖可改名标题；workflow.json 是归档完成标记，不维护额外可变索引。
bindings.json 的 ui 字段包含身份、显示名称与 bboxSha256，拼装会校验 Bbox 的内容哈希。
普通画布移动不重复归档；切图未完成、旧资源过期时仍可保存画布，但不归档为新的就绪资源包。
归档保存失败时返回错误，不宣称保存成功。已有独立归档不依赖画布文件继续存在，不自动清理。

CLI 无需开启浏览器：`canvas ui-archives --target-dir <项目> [--canvas-id <ID>]` 只读列出名称、
UI ID、版本、阶段和项目相对路径；`canvas archive-ui --target-dir <项目> --canvas-id <ID>` 为已保存
旧画布补归档，不读取未保存页面，也不重新生成。组装选定 resources 记录，不擅自选另一个“最新版本”。
导出 ZIP 同样包含 bbox.json、bindings.json、分类 PNG 和保留 assets/ 相对路径的两张参考图，
换电脑后按 Skill 导入即可，不依赖原机器的绝对路径。

官方合批模板与历史分类模板共用槽位绑定链路：生成前固定 uiAtlasPlan（Bbox 快照、网格、每格元素 ID/状态），
生成记录保留该快照。切图按行优先顺序关联 PNG，保留内容区域 contentRect，不按外观或文件名猜测。
非可选识图流程从识图清单按控件、图标、装备、面板、人物和背景自动分批，每张最多 5×5。
分类内按 Bbox 宽高与长宽比合批：横长、竖长和普通素材分开，批内宽高差各不超过四倍、
长宽比差不超过三倍。长宽比达到 3:1 的长条每批最多五格；方形输出按素材比例选择行列，
不强行填满 5×5。槽位排序随尺寸调整，元素 ID、状态与 duplicateOf 绑定一起移动。
同一识图结果下，已生成批次完整覆盖该分类时继续使用生成记录中的分批快照，避免升级排版规则后重复生图。
旧批次未完整覆盖且与当前分批不兼容时，在新增卡片和提交生成前停止，保留原结果；新模板使用当前规则。
换稿后不再需要的续批按空分类跳过预排、分离和切图，保留卡片及原图文件，导出与归档排除旧结果；后续清单重新需要该批次时恢复执行。
模板提示词使用当前通用规则，不携带示例元素编号和固定坐标；识图改变后旧清单拒绝复用。
导出终点在分类 PNG 之外附带 bbox.json 和 bindings.json，后者记录实际 ZIP 路径和 SHA-256、
默认/按下态、复用关系与确认状态。缺件、未核对顺序的素材不能直接拼 UI；格数正确不等于内容正确。
生成图不符合等分网格时，可在图集解析中选「按槽位调整裁切框」，按显示的元素 ID 和状态调整
各槽位的源图区域；槽位数量和顺序固定，区域不得重叠，必填槽位不得为空。核对后显式确认，
保存的区域会随资源卡保留，重新打开可继续使用；这是人工校正路径，不代表模型自动排版通过。
CLI 同一路径为 preview-image-assets 传入 cut.mode=grid 和 cut.regions，查看预览后再 confirm-image-assets。
旧素材只有在已有明确映射记录时才可回填为 recorded；本次回填不代表重新验证模型识别质量。
拼装脚本按 Bbox 和显式绑定生成图像与 Label，可确定性裁去 PNG 透明边距到新目录，不修改原文件。

## 图片尺寸与横竖屏

每张图片的真实宽高从文件读取，比例由宽高计算；卡片外框尺寸和画布缩放不是图片像素尺寸。
图片卡片打开、替换或生成后，按实际图片比例调整预览区高度，保留位置与当前宽度；
标题栏单独计入卡片高度，拖动缩放保持图片比例。过高卡片等比缩小，不裁剪或拉伸图片。
CLI 使用 `canvas update-nodes` 修改卡片 `width`/`height`；图片只传其中一边即可等比适配另一边，
同时传两边时须符合图片比例（卡片高度包含标题栏）。纯尺寸修改不重置生成结果，也不改变画布视口。
导入、替换、生成结果和 CLI inspect 均提供 imageInfo，沿现有引用链提供唯一原稿 originalImage；
多原稿无法唯一确定基准时，跟随模式提示选择固定输出比例，不擅自挑一张参考图。

游戏 UI 模板的去文字、背景准备、三类标注和完整主面板默认「跟随原稿」（aspectRatio=source）。
新旧画布都支持；旧实例仅升级仍匹配模板原始提示词及 9:16 默认值的步骤，保留已修改的设置。
图集保持独立比例/网格；参数面板及 CLI 可手动选择固定比例，不改变画布位置或缩放。
识图开启时的标框按原图像素绘制，识图关闭时的生图标框使用相同尺寸策略。

识别常用比例 1:1、16:9/9:16、4:3/3:4、3:2/2:3、5:4/4:5、21:9/9:21，允许 1% 比例误差。
非常见比例在卡片及生图前提示可能影响构图/切图。输入比例识别不等于输出支持：当前接口不支持 9:21，
也不支持任意比例；跟随模式会在付费提交前阻止不支持的比例，提示选择固定输出比例，不自动裁剪或拉伸原稿。
输出长边由原有 1K/2K 选项控制，目标宽高与发送的比例一致。

每次生图按实际参考图片分别附带尺寸，并保留原稿基准、请求尺寸和返回尺寸；
生成记录中的 referenceImages、originalImage、parameters.targetSize、resultImageInfo、warnings 可供 CLI 核对，
submittedPrompt 保存附带尺寸信息的实际请求提示词。
在线 CLI inspect 的 state.imageSizing 汇总该次请求尺寸、参考图、原稿、实际结果与告警；
离线 inspect 的 imageInfo 从图片文件读取，不凭历史请求推测尺寸。
模型返回比例偏差超过 1% 时保留图片并提示，模板中的该步骤保持待处理，其下游不自动接续；
其它独立分支继续，不因此自动重新付费生成。

## 本地 Bbox 预排步骤

「游戏UI制作 · Bbox预排参考图（实验）」模板在图集生图前接入带有 `uiAtlasPrelayout: true` 的图片卡。
该卡点击「执行预排」或通过 CLI 单卡 run，新批次按当前 Bbox 原尺寸裁片并紧凑排列，
不调用生图或识图 API、不消耗积分。必须先完成当前去文字图的识图；全组运行仍需生图授权。
结果作为独立图片卡可查看和复用，下游生图沿用同一批次槽位并提示模型保持预排位置。
各批次完成预排及保存后即可并发生图，不再限制为 3 张；本地预排和切图仍共用单任务通道，画布保存串行。
换图或更新 Bbox 后重做预排；服务端校验原稿/去文字图的尺寸、哈希和下游槽位一致性。
预排画布留白与素材间隔使用 Alpha=0，裁片保留来源透明度，不铺绿底或洋红底；矩形内仍可能带原稿背景。
分离提示词要求直接输出带真实 Alpha 通道的透明 PNG；新结果记录 cutoutColor=transparent，切图不做颜色抠底。
当前支持 PNG 去文字图；新批次按原稿 Bbox 像素宽高四舍五入，素材间隔 8 像素，不缩放入格。
去文字图分辨率不同时只映射到原稿坐标基准。2048 是单边上限，不是固定画幅；
按分类装入后比较换行宽度，以实际占用选择面积最小的支持比例画幅，不缩放素材、不铺满空白大图。
放不下才续批，单项超过 2048 像素直接停止。
nativeLayout 保存图集尺寸及实际裁切矩形；分离输出必须保持尺寸和位置，切图复用显式裁框，正常态与按下态分别绑定。
模型输出常有整体偏移或略大于槽位，切图预览按 Alpha 连通区域校正：先把尺寸相近（0.75～1.35 倍）、
位置相近且唯一的大主体与槽位一一配对（整张图集下移、拉长时也能对上）；其余主体只碰到一个槽位时归该槽位，
碰到多个槽位时取重叠过半的槽位，粘连区域按像素归属最近槽位（8 像素内）拆分；
主体超出槽位时等比缩入原槽位尺寸。不与任何槽位重叠的大块多余主体直接舍弃。
槽位缺主体、或存在大于 16 像素且不与任何槽位重叠的多余主体时，自动校正不成立：改按原槽位裁切并记警告，
不让该批失败；需要时手动调整裁框或重生该批。
主体触及图集边界（模型画出画布，常见于大幅人物）时照常校正；是否缺边在最后复核时看图确认。
手动编辑裁框后改用手动裁框，不再自动校正；重置恢复自动校正。与 Web 版不同，粘连区域拆分而非直接失败。
Maker 来源的原尺寸分离使用 edit_image 编辑唯一的预排输入，而不是将预排图当成风格参考重新生成。
实验模板的单图去文字同样使用 edit_image，减少重新构图；仍需检查角标文字和非文字底板是否保留。
历史纯色原尺寸资源切图仍清理透明边界附近四像素的底色溢色；新透明结果直接保留 Alpha。

分离结果移位时，可在「按槽位调整裁切框」或 CLI preview-image-assets 的 cut.regions 中平移裁框。
必须保留原槽位名称、顺序、数量和宽高，不允许重排、缩放、重叠、越界或空白占位；经预览确认后，
实际裁框保存到 imageAssetsInfo.regions，生成时的 nativeLayout 与原稿 Bbox 不改。重新打开及同来源续跑复用已确认裁框。
空格错误列出 item、元素 ID、状态和分离卡 ID。若图上确实缺失素材，只调整该分离卡提示词并重新生成该批，
核对并确认切图后继续原分组；不重跑识图、预排或已完成批次，不自动反复重生。
预排图仍含原稿背景和遮挡，不能直接替代分离结果作为透明 PNG 交付。
旧网格产物不迁移、不覆盖；不把旧素材按新坐标解释。普通游戏 UI 模板按透明间隔切图，不依赖 Bbox 网格。
预排裁片仍带有原图背景与遮挡，素材分离和按下态效果仍需检查模型输出。
原「游戏UI制作」模板不启用；实验模板及其个人副本在保存、重新添加和续批时保留此处理步骤。
个人模板的资源卡按上游 UI 槽位记录或预排连线识别，保留自动抠底及绑定流程。

## 元素识图与 Bbox JSON

UI 设计稿使用普通图片卡的专用配置，选中后顶部提供「识别 UI」和有结果时的「查看标注」。
标注在独立弹层查看；图片卡扩展规则见 [图片功能开发规范](MAKER_CANVAS_IMAGE_FEATURES.md)。
识图仅使用 Server API（默认）或自定义 API；本地 AI 与 ChatGPT 网页来源已停用。
旧来源读取时按 Server API 生效，不改写原配置；API 不可用时提示恢复接口，不切换渠道。
CLI run UI 分组或图片步骤默认开启识图；显式 input.recognition=false 才走无识图对照。
工作流按钮沿用已保存开关；有效来源按设置和 Server API 可用性解析，已提交任务不切换来源。

同一界面顺序识图两次，不合并提示词，不加载额外识图 Skill 或旧稿答案：

1. 只传去文字图，识别可独立切图的 UI 单位。类型限定 icon/frame/panel/button/tab/title，
   ID 从 E001 递增；重复实例逐个记录，按钮底板与符号、物品格与物品图、每颗星星分别保留。
   相同素材可由 duplicateOf 引用同类型原始元素，保留每个实例坐标；分批只生成代表素材，
   槽位 elementIds 同时绑定所有重复实例。保留识图返回的标记，不按名称或二值轮廓重新推断。
   复用要求形状、颜色、纹理和状态一致；异色装备框、选中态和空心/实心星星不能仅因轮廓相似合并。
2. 只传原 UI 设计稿及第一次清单，识别文字和数字，ID 从 T001 递增。
   保留实际文本、parentId、role、align、color、bold、cutout=false；不重复识别图标和底板。
   普通文本后续生成 Label，不进入 PNG；特殊美术字仍沿原稿独立支线处理。

两次输入必须来自同一画布的连线：去文字卡直接引用唯一原稿。读取真实图片尺寸和 SHA-256，
两张图尺寸不同则在第二次前换算切图框到原稿像素；不从卡面尺寸或图集格子反推原稿位置。
缩放换算假设去文字图保留整屏布局；裁剪、移位或重绘形变需要视觉复核，不能靠比例换算修复。

### 本机设置

控制台右上角齿轮仅提供 Server API 或自定义 API 识图。只有自定义 API 需要填写 Base URL
和 API Key；模型固定为 gpt-6.1-sol，Key 只保存在本机且不回显。
接口须支持 image_url data URI、response_format=json_object 和 reasoning_effort=low。
本机 HTTP 仅允许 loopback，其他地址要求 HTTPS，禁止在地址里写凭证、查询参数或片段。

设置保存到 Maker 用户目录 ui-vision.json（默认 ~/.taptap-maker，支持 TAPTAP_MAKER_HOME），
复用原子私密文件写入，文件权限 0600；不写入项目、画布、模板或日志。页面只收到来源、Base URL 和已配置状态，
不回显 Key。修改 Base URL 必须重填 Key，避免旧密钥发往其他服务。
保存与清除设置不调用模型；API 来源点击「识别 UI」后顺序执行两轮识图，图片发送到所选服务，不再弹出费用确认。
设置下次读取即生效，无需重启。旧 TAPTAP_MAKER_VISION_CONFIG 仅兼容 gpt-6.1-sol 条目，
本机设置优先；不再提供任意多模型比较。

### Server API 与可用性检查

默认使用 Maker `model-inference`，设置、CLI 与画布按当前项目检查接口可用性。
检测只 GET 随机 UUID 的任务查询地址；HTTP 404 且 error.code=MODEL_INFERENCE_NOT_FOUND
表示查询接口可达，普通 404、鉴权失败、网络异常或 5 秒超时均视为不可用，不提交模型请求。
不可用时 Server API 显示暂不可用，保留 API 来源，不自动降级。
已选自定义 API 不被覆盖。已有任务继续查询或显式恢复，不因检测失败换渠道重做。
可信本地进程使用已有 Maker PAT、当前绑定项目和环境，顺序提交去文字图与原稿；
服务端固定 `gpt-6.1-sol / low`，客户端不传模型覆盖参数，沿用本地 Bbox 校验。
图片按原尺寸发送，提交前检查 10 MiB、单边 8192、总像素 4096² 和提示词 10000 字符限制。
服务端第二轮仅识别原稿文字，不将完整切图清单放入提示词；返回的空父级按文字中心所在
的最小已知底板关联，未命中则保留 null，文字坐标不变，避免大清单超限且不增加付费轮次。
耗时累计每次执行和查询的实际等待时间，不计两次操作之间的暂停。

请求记录保存在项目 `.maker/canvases/recognition-attempts/`，每轮保存项目、环境、
原提示词、图片路径与 SHA256、稳定幂等键及远端 request_id。图片变化时拒绝恢复。
查询只 GET 已有任务，不提交下一轮，也不补扣积分；后台原请求 POST 显式传
`allowPaid: true, recover: true` 才允许继续下一轮、无 ID 的原键恢复或结算失败恢复。
已有 ID 优先查询；明确不可重试的失败不重发 POST，超过 24 小时的旧请求不重放。
CLI 使用 `recognize-ui --input '{"id":"去文字卡ID","recover":true}' --allow-paid` 接续原请求，
无需操作浏览器确认框；旧版清掉 pendingId 时，可在 input 中加原识图记录的 attemptId 恢复关联。
恢复必须找到同画布、同卡片、同图片的原记录；两轮已成功时只重新做本地校验，不再调用模型。
识图明确失败后清除本地 pendingId，保留原请求记录与每轮原始输出，并在错误中返回原请求编号。
可修正后回填 Bbox，或显式重新识图；需要重验原记录时通过 attemptId 恢复关联。running/unknown 继续保留 pendingId，不自动重提。
文字颜色先移除空白再校验 #RRGGBB，
无效颜色报出文字 ID 和 color 字段，不丢弃文字或用默认颜色掩盖问题。识图查询与恢复等待窗口为 375 秒。
每轮操作最多一次远端请求，每轮首次提交通常等待结果；运行中可后续查询。
远端错误码、重试标志、用量和积分随任务保留，两轮积分均已返回时在结果便签显示合计，
重复查询替换原值，不累加；未返回积分不代表免费。接口可达不代表模型推理或扣费一定成功，提交后的错误仍按原任务处理。

### 固定导出契约

识图结果以 uiRecognition.result.bbox 为权威 Bbox，现有 elements 是用于切图的派生视图。
面板「导出 Bbox JSON」下载如下固定结构；CLI inspect 可读取相同 bbox 数据并保存到工作流目录：

    {
      "version": 1,
      "coordinateSpace": "design-pixels",
      "bboxFormat": "xywh",
      "design": {"path": "assets/image/canvas-<uuid>.png", "sha256": "<sha256>", "width": 1080, "height": 1920},
      "cutSource": {"path": "assets/image/canvas-<uuid>.png", "sha256": "<sha256>", "width": 1080, "height": 1920},
      "elements": [{"id": "E001", "name": "按钮底板", "type": "button", "bbox": [100, 200, 240, 80], "parent": null}],
      "texts": [{"id": "T001", "text": "确认", "bbox": [160, 220, 120, 40], "parentId": "E001", "role": "button", "align": "center", "color": "#F2D48A", "bold": true, "cutout": false}]
    }

所有导出 bbox 统一为原 UI 设计稿像素 [x,y,w,h]，不是归一化、xyxy 或图集位置。
切去文字图时按 cutSource/design 宽高比例反向换算；组装时直接使用原稿像素。
程序校验版本、图片身份、范围、编号、父级和循环；文字允许空数组，切图清单不能空。
各次完整结果和只读便签保留；旧版单次清单仍可查看，但没有文本 Bbox，不能冒充双次识图结果。
选择其他清单或修改开关会标记下游待更新；分类无元素显示「无需生成」，不复用示例包。

请求编号在发送前落盘，第一次完成也保存切图阶段结果。第二次失败或超时保留第一次清单，
但不选用不完整结果，不启动下游。Server API 查询已有远端请求并复用已保存输出，自定义 API 只读本地记录；
查询不会提交下一轮或重放模型调用。服务重启后无法确认的请求为 unknown，按原来源查询或恢复。
鉴权、额度、限流和输出校验错误分别提示。字段校验通过不代表视觉无遗漏或像素级一致。

## 当前流程：保留位置、冗余切图、两次对位

识别阶段先记录原设计稿中的元素身份和位置，再开始生图式切图。红框图只是可视化，
不能替代机器可读的布局清单。所有坐标采用原始设计稿像素，不从生成图集的位置倒推。
本流程复用现有画布图片和资源卡、UI 编辑器对照功能，不新增画布按钮或生成任务系统。

1. **识别并保存布局**：原图尺寸、文件哈希，以及每个元素的稳定 ID、矩形、父元素、类型和
   同级绘制顺序写入布局 JSON。普通文字也保留为 Label；美术字记录为图片元素。
   图中相似元素逐个编号，素材相同不代表元素相同。修正框的位置时保留 ID，不因排序重新编号。
2. **生成并绑定素材**：生成任务或图集槽位与元素/素材编号显式对应。图集网格坐标只用于裁图。
   导出后记录 PNG 的路径、哈希和尺寸；同一素材可以绑定多个元素，默认/按下状态绑定同一按钮。
   生图结果顺序仍需核对，不能只凭模型承诺或文件名猜测对应关系。
3. **保留冗余**：允许同一对象的多种候选、备用状态和多切的底框，作为 reserve 素材保留。
   不因为没用于本次布局就删除，不把备用素材自动变成 UI 节点。原稿漏项仍应补识别，
   不能把“多切了素材”当成“原稿内容完整”。选择备用素材时显式改变绑定。
4. **第一次组装**：程序按布局记录及绑定生成 UI JSON；父子相对坐标由全图坐标换算，
   同级层级按 elements 内的先后顺序，背景、图标、文字各自保留。缺少绑定则停止，禁止视觉猜配。
5. **第二次对照纠偏**：Agent 在 UI 编辑器中打开组装结果，查看左右/重叠截图，对照同一份原稿，
   按已有 ID 检查偏移、尺寸、层级、遗漏和状态对齐。几何偏差写入独立 corrections JSON，
   保留 before、after、reason 和截图证据路径；重新组装并再次看图。层级或素材绑定错误需修正
   布局清单，再重新复核，不能用移动坐标掩盖。复核过程不重新匹配相似对象、不删除冗余资源。

“第二次对照”目前由 Agent 看图完成，工具不自动进行图像识别或判断视觉通过。
纠偏记录绑定完整布局哈希、设计稿哈希及调整前坐标，旧版本记录不能套用到新布局。
没有纠偏记录的输出明确为待视觉复核；有记录只表示已记录复核，不表示像素级自动验收通过。
当前香蕉物流是从已认可的重建结果回填位置，provenance 必须使用 reconstruction-backfill，
不能把它说成之前切图时已记录。新设计稿在识别时记录则使用 recognition。

### 布局文件与组装工具

已有双次识图 Bbox 时，可将 assembly.json（bbox 为完整导出对象、assets 为资源记录、
bindings 为 {elementId,assetId,pressedAssetId?} 数组）作为组装输入。
脚本按原稿框生成图像节点和 Label，保留文本、对齐、颜色和粗体，自动换算父子相对位置，
额外输出 layout.json 用于后续 corrections。没有素材绑定即停止，不猜配；备用素材不入节点。
参考源与素材目前均须为 PNG。字号按墨迹高度初拟合，字体与图层顺序仍需编辑器对照。

Skill 工具 skills/maker-ui-workflow/scripts/assemble-ui.mjs 不调用付费模型、不写 meta、不修改已打开画布。
发布时打包依赖，随 npm 与客户端插件提供；原 scripts/assemble-maker-ui.mjs 保留兼容入口。
布局文件放项目开发资源目录，UI 和正式 PNG 放 assets。命令输出目录必须不存在，避免覆盖手工编辑。

    node scripts/assemble-maker-ui.mjs <项目根目录> <layout.json> <新输出目录> [corrections.json]

输出 assembled.ui.json、assembled.reference.png 和 assembly-map.json。后者记录最终位置、
原始位置、素材引用次数与备用清单。资源仍引用原项目 assets，不重复复制全部切图。
把 UI 导入项目后显式调用 generate_resource_meta，再用 UrhoxUIEditor 检查和对照。

布局 JSON 的 version=1，coordinateSpace=design-pixels，rectBasis=asset-canvas。
design 包含 path（assets/ 相对路径）、sha256、width、height；assets 列表的每项具有这些
图片字段及 id、role（bound 或 reserve）。素材可选 contentBounds 记录透明通道内容边界，
只用于复核，不隐式改变放置坐标。elements 中每项包含：

- id、parentId（唯一根为 null）、type（Panel/Button/Label/Image）。
- render 区分 container、image、text；image 在切图绑定完成前不能组装，防止漏图静默变为空面板。
- rect=[x,y,width,height]，全部是设计稿绝对像素坐标；根矩形与设计稿一致。
- props 存储颜色、文本等编辑器属性，不允许偷偷覆盖位置、尺寸、图片引用或添加整体变换。
- assetId 可绑定默认图片；Button 的 pressedAssetId 可绑定按下图片；Label 无需切图。

rect 表示整个 PNG 画布的放置范围，不能混用按钮主体边界与含阴影/透明边距的画布边界。
先裁透明留白或统一状态画布，再记录资源尺寸和哈希；默认/按下态要检查主体锚点是否一致。
切图若发生形变，坐标记录不会自动修复形变，应选择备用或在编辑器调整，不宣称完全无误差。
当前工具只组装固定坐标的静态 UI，不处理旋转/缩放节点、动态列表、百分比和响应式布局。

纠偏 JSON 的 version=1，layoutSha256 为解析后 layout 对象 JSON.stringify 的 SHA-256；
review 包含 designSha256 与 evidence（实际对照截图路径），adjustments 每项为
{id,before:[x,y,w,h],after:[x,y,w,h],reason}。没有偏差时可以记录空 adjustments。
移动父节点时未单独纠偏的子节点一起移动；对子节点显式纠偏使用新的全图坐标。
修改父节点宽高不会隐式缩放子节点。原始布局不被覆写，纠偏只作用于本次输出。

验证命令：node --test scripts/test-maker-ui-layout.mjs。
它检查重复元素复用、冗余保留、父子纠偏、过期记录、图像身份、非法坐标及禁止覆盖。

## 复用已保存的 UI 拆解模板

在画布的「添加模板 → 我的模板」中添加已保存流程，再替换实例的原设计稿。模板保存卡片、
连线、提示词和示例结果，但不会把旧设计稿的元素清单、标框、网格和布局坐标自动适配到新图。
旧结果只供参考，不能在替换首图后直接当作新设计稿的交付物。

复用时由 Agent 跟随以下步骤，继续使用现有画布操作，不新增自动工作流引擎：

1. 在新原稿上重新记录元素 ID、位置和状态。重复的奖励格保留不同实例 ID，可以共用素材；
   开关的开/关状态与按下反馈分别处理，不能仅把关闭底图当成开启按钮的按下态。
2. 更新去文字、按钮标注、图标标注、背景准备和美术字的输入及清单。美术字识别仍引用原稿，
   不能只看已经去掉文字的图片。每条提取提示词分清保留、移除和输出要求。
3. 查看真实生成结果，只返修缺件、图层混入或形状错误的组件。纯色底先处理为透明，再展示
   最终素材卡。清理几乎不可见的孤立像素后再确定透明边界，避免它们撑大尺寸、使主体显示偏小。
4. 不假设模型严格遵守规则网格。主体跨格时先按完整边界重新排版，再查看网格预览、确认和导出。
   默认/按下态统一图片画布与锚点，备用资源保留但不自动放入 UI。
5. 导出 PNG，按新布局记录组装 UI JSON，显式生成 meta，并在 UI 编辑器中做左右和重叠对照。
   保存画布后重新打开，确认展示的是新结果、资源可下载且文件引用有效。

目前可以复用流程结构，再由 Agent 分阶段接续与复核；不能承诺只换首图、无人检查就自动生成
全部可用素材和 UI。Agent 的透明处理、重新排版及视觉纠偏也不能表述成模板已有的一键能力。

## 历史多轮识别预设

下面描述仓库已有的早期预设；实际项目按上面的布局记录与双重对位流程补齐数据，
不因旧预设限制而删除冗余切图，也不把生成的标框图片视为已保存坐标。

本仓库新增的“BikeKingBanana UI · 多轮识别→去文字→分层导出”预设，面向
“奥德彪拉香蕉/BikeKingBanana”的角色、背包、每日任务和七天签到界面。它使用现有画布
图片卡、便签卡和游戏资产卡，不引入新的 MCP tool 或第二套任务系统。

## 画布中的阶段

每个界面分成同样的 5 个阶段：

1. **设计稿**：以项目已有界面稿作为可重复的离线起点；卡片的生成参数固定为 model=gpt、
   resolution=2K。Maker 远端的 gpt 图片能力优先使用 GPT Image 2.5 Flare。需要重新设计时，直接在
   设计稿卡片上执行生成，不能把识别候选当成设计稿。
2. **三次独立识别**：三个候选卡分别检查完整性、遮挡关系/漏项、交互与分层。候选图用于标框和
   复查，不视为最终组件清单。
3. **共识复核板**：把三张候选结果连接到共识卡，生成合并后的复核板。人工确认保留、删除和
   缺失项；缺失项补充到便签，再只重做对应识别或图集阶段。
4. **去文字与分层图集**：只保留确认过的组件，所有文字、数字、价格、百分比、红点和动态
   状态移到 code_layer，图集中按 4×3 单组件排列，纯洋红背景用于抠图。
5. **游戏资产**：确认图集已经没有文字、残影或合并图层后，使用现有图集预览和确认流程导出
   独立 PNG。未确认的图集不能直接导出或进入游戏资源目录。

设计稿和每个阶段的生成结果都保留在画布中；未知的付费结果只查询原任务，不自动重提。
三次识别不是“多数票自动通过”：冲突、低置信度和可能遗漏必须留在复核板上交给用户选择。

## 组件分类

识别时固定使用以下分类：background、common_control、title_icon、tab_or_menu、
panel_or_frame、icon_or_item、portrait_or_character、gameplay_entity、decoration、
code_layer。背景、底图、背景框、前景格子、按钮状态、页签、滑动条、进度条、图标、头像/立绘、
道具槽和装饰层分别记录；能够由程序绘制的纯色框、进度条、禁用蒙层和文字不切图。

每个独立点击、缩放、显隐或动效对象单独成项。状态组至少记录 normal/selected 或
normal/pressed，同组对象保持相同尺寸和锚点。前景格子与底图必须分开，不能用整屏截图或一张
合成图冒充可交付素材。

## 现有画布能力的边界

模板预先连接设计稿到三张识别候选，并连接图集到游戏资产卡。识别候选、共识板和去文字图集在
没有真实结果前不会伪造素材路径，因此每完成一个阶段后，需要在画布中把真实结果卡连接到下一阶段。
这一步是有意保留的确认门：它防止未完成或结果未知的付费任务被队列自动接续。

交付前至少检查：浅色和深色底上的透明边缘、文字是否完全由程序层绘制、组件是否有独立透明
边界、状态组锚点是否一致、图集是否存在多余组件，以及从独立 PNG 重建后的界面是否仍能对齐
原设计稿。通过后才复制到项目正式资源目录；候选图、图集原图、报告和对比图留在过程目录。

## 如何继续扩展

新增界面只需在模板的 screens 清单增加设计提示词和一张离线参考图，沿用同一组识别、复核、
去文字和导出门禁。若界面需要超过 12 个组件，应先在复核板确认数量，再调整图集网格和导出规格，
不要为了填满网格生成清单外素材。

完整示例只供预览；新实例只添加原稿、识图输入和去文字步骤，不复制固定分类与示例续批。
模板仍标记 cliOnly（实例为 templateCliOnly，保留旧 CLI 语义）。015 分组栏的「开始：自动生成 UI」与
CLI `canvas run` 调用同一个协调器，一次跑完，不在中途停下等待确认：

1. 准备识图输入 → 去文字 → 两轮 API 识图；原稿保持原格式（JPEG 也直接送 edit_image 与识图），
   不在此处转 PNG，转换后体积变大会导致上游编辑失败。美术字预排需在本地读取原稿像素，
   画布执行时在浏览器内转成同尺寸 PNG，随本次请求以 base64 `designPng` 发送，
   服务端只在内存中校验尺寸并裁切，不在项目中另存原稿副本；
2. 美术字与背景按默认值直接应用：识图 role 为 title 的文字做成美术字，识图未找到背景元素时额外还原背景。
   之后可用「调整美术字/背景」改选（CLI 传 `artText/background`），改选同样自动跑完；
3. 预排、分离生图与切图作为一个队列执行，沿用现有并发；
4. 队列结束后自动组装：控制台从已保存画布的同一版本 resources 归档导入 `assets/ui/<ui>/<版本>/`，
   组装 `ui/assembled.ui.json`，生成资源 meta（Python 未就绪时自动准备一次），执行引用检查；
5. 最后一步显示「打开 UI 编辑器」和「AI 复核修复提示词」，提示词列出全部待处理项和修复步骤，
   交给 AI 按 maker-ui-bbox-workflow Skill 复核修复。

不中断的规则（每步最多自动重试 2 次，均写入运行日志）：

- 识图无返回或结果未知：用原请求编号与幂等键重试，不重复计费；
- 生图失败或结果未知：先查询原任务，有结果就取回；没有结果才重新提交，可能多计一次费用；
- 切图自动校正失败时按原槽位裁切，原尺寸图集缺格时照常完成，都只记警告；
- 组装不再要求逐批确认：未复核的切图照常组装，没有任何素材的元素本版略过（子元素挂到最近的保留父级），
  三类情况记入交付记录 `review.unreviewed / missing / unbound`；
- 只有服务重试后仍不可用、项目或配置错误时才结束，并给出原因；再次点继续只补未完成的步骤。

同一归档版本复用已有交付，未完成的 meta/检查只补这两步；同组并发提交返回 `ASSEMBLY_BUSY`。
原稿非 PNG 时，画布在组装时同样以内联 `designPng` 发送 PNG 像素
（CLI 用 `--design-png` 指定项目内同尺寸 PNG），服务端校验尺寸后写入交付目录的
`source/design.png`；缺少时返回 `NON_PNG_SOURCE`。
逐批预览确认仍可在最后一步「逐批复核切图」中手动进行，或由 AI 用 preview/confirm-image-assets 完成；
确认后 `assemble-ui --new-version` 生成新版本。

分组布局沿用 Web 版：第一行为原稿、识图输入和去文字卡，其后每行三组「预排 + 分离」，
切图卡收起在资源包内，资源包置于最后；同步批次和图片卡尺寸变化后自动重排。
分组底色半透明，组内连线可见。
分组栏「打开 UI 编辑器」以 `project=<项目键>` 打开当前项目的交付文件，不受控制台上次所选项目影响；
编辑器按 UI 文档宽高默认横屏或竖屏（宽大于高为横屏），项目发布方向只在组件或无尺寸文档时兜底。

付费步骤由用户点击（或 CLI `--allow-paid`）授权，过程写入运行日志，不逐步确认；未知结果先查原任务，
查不到结果才按上面的规则自动重新提交。
AI 也可分步调用 sync-ui-batches（input.id 为分组 ID，
input.artText 为 Bbox 文字 ID 数组，input.background 为布尔值）创建缺少的预排、分离、PNG 与资源包；空分类不建卡。
未选中的美术字与额外背景支线标记 uiEmpty 保留（不导出），再次选中时恢复并重新执行。
停用时生图卡记录 `sourceSnapshots`，切图卡记录单个 `sourceSnapshot`（保存校验不接受切图卡带列表）。
美术字每个 ID 独立按原稿像素框预排、分离和裁切，沿用普通素材的原尺寸布局与来源校验，
识图仍只读取同组去文字卡的权威结果，不在原稿重复识图；兼容旧 artText=true 的单主标题支线。
实验模板原尺寸图集内同时含同 ID 的正常态和按下态时，切图预览与 PNG 输出均从正常态
本地压暗 20% 派生按下态，保持 Alpha、轮廓、尺寸与位置，不依赖模型重绘双态；
跨批次状态仍保留生成结果并逐项复核。普通模板不受影响。
分离卡的“输出排版校正：”单行补充会传入本次生成，不会被自动槽位提示词覆盖。
实验模板整包导出校验全部资源卡已接入并完成、
识图版本一致、所有元素及按钮/页签双态均有绑定；部分资源不得作为完整包导出，普通模板不变。
background 只决定是否额外还原清单外的环境背景，纯弹窗不默认补场景。
同步沿用 revision、任务阻塞和来源校验，不调用模型、不重复建卡、不删除已有产物；
超过画布容量时整次停止。保存为个人模板和 ZIP 导入导出保留 CLI 执行标识。
预排使用当前 Bbox 裁片组成参考图，随后由生图模型
分离背景；新实例仍需完成当前输入的识图与生成，示例不代表新任务已完成。
实验结果需逐批复核，部分底板、图标和发光效果可能仍有粘连或重绘。

按 CDN 优先、GitHub 备用加载；导入时重映射到当前项目，不依赖维护者的个人模板路径。
模板详情的资源包按来源分类展示全部 PNG，分类内可展开，资源区可独立滚动；面板和背景置后。
