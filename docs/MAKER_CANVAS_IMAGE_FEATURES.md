# 图片卡专用功能开发规范

## 边界

CanvasNode.type 描述内容结构。image 始终管理单张图片；资源集合、视频、模型等继续使用
既有独立类型。扩图、下载属于操作，不新增卡片类型。UI 识图、分类拆图、标注图和二合图标
通过有类型的附加配置启用，不创建继承层级或任意 JSON 插件槽。

图片卡共用图片尺寸适配、布局、拖动、连线、复制、保存和撤销。专用功能不得替换卡片根内容、
跳过尺寸适配或把操作按钮放进图片卡面。入口位于选中卡片后的顶部菜单；复杂参数和结果在
独立面板或弹层内展示。

## 功能入口

src/maker/canvas/imageFeatures.ts 是功能标识、配置字段、专用菜单和扩图限制的定义入口。
业务仍由现有模块负责，定义表不保存任务状态、不调用模型，也不承担渲染全部卡片的职责。
功能配置是启用依据，不按卡片标题、图片文件名或是否曾生成来猜测用途。

| 功能        | 配置来源      | 执行模块                            |
| ----------- | ------------- | ----------------------------------- |
| UI 识图     | uiRecognition | uiRecognitionUi / canvasRecognition |
| UI 分类拆图 | uiExtraction  | uiRecognition / generationUi        |
| UI 标注图片 | uiAnnotation  | uiRecognitionUi                     |
| 二合图标    | mergeIcons    | mergeIcons / generationUi           |

基础图片没有专用配置时，不出现识别 UI、查看标注入口。二合图标保持既有参数编辑入口，
扩图限制由统一功能规则读取。后续新功能必须补齐有类型的配置校验，并接入此定义入口；
不为尚未存在的功能添加扩展层。

## UI 输入与结果

uiRecognition.inputRole 为 design 或 text-free；旧数据未填写时按 text-free 处理。
专用导入建立 design 角色；UI 模板实例通过既有原稿到去文字稿连线给原稿标记 design，
不额外保存第二份来源关系。原稿角色默认不参与自动识图步骤，去文字稿仍是双次识图执行节点。
API 调用必须有唯一、就绪的原稿与去文字稿；uiRecognitionInputs 在网页与服务端复用。

原稿卡可以查看下游去文字稿保存的结果，不复制 Bbox。UI 标注弹层始终使用原稿坐标，
图片和框放在同一个 SVG viewBox 中。显示开关和预览尺寸是临时界面状态，不写入画布。
打开时校验图片哈希和尺寸；替换任一输入后，旧结果不可作为当前标注或切图依据。

识图仅使用 Server API 或自定义 API，沿用 Maker 识图设置和认证边界。
本地 AI 和 ChatGPT 网页识图入口已停用；旧结果与回填协议保留兼容，不作为新的识图渠道。
点击查看标注不提交识图任务，也不计费。

旧 uiRecognitionCard 仅在文件读取/保存边界迁移成 design 配置；不再持久化该展示标记。
单张原稿上的本地识图结果可用于查看，不能因此绕过双次 API 识图的去文字输入要求。

## 复制、替换与模板

- 普通复制保留同一图片的完成结果和用途，清除 pending 请求身份。依赖连线未复制时，
  需要原稿关系的结果不可继续使用，不猜测来源。
- 保存模板保留用途、配置及已完成的识图示例，清除 pending 请求身份；导入时重映射示例图片与 Bbox 路径。
  实例化到画布时清空识图结果和选择项，下游保持 templatePending，示例不能跳过新稿识别。
- 替换图片保留用途配置；旧结果可保留记录，但只能在图片身份和依赖均匹配时使用。
- 上游变化沿用既有依赖失效机制；不新增另一套来源映射、任务队列或重试器。
- UI 与 CLI 使用同一配置校验及业务规则；界面隐藏按钮不能替代服务端输入校验。

## 新功能验收

修改前检查相邻模板、自动化调用方、数据校验和复制规则。验收至少覆盖适用卡片的入口、
普通图片无专用入口、缺输入、换图失效、复制/模板清理、保存重开。涉及付费请求时继续遵守
原任务查询和未知结果不重放规则。

图片功能变更使用定向测试和浏览器操作验证；模拟请求只能证明交互链路，不能声称真实生成
质量通过。新增有独立交互结构的内容类型前，先说明为何图片附加功能无法满足需求。
