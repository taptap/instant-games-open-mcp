# Maker 本地控制台

右上角齿轮「设置」提供识图方式（Server API、自定义 API）与生图方式
（Maker MCP、本地模型、自定义 API）。两者复用已保存的命名 API 配置；新增、编辑弹窗填写
名称、Base URL、API Key、模型名称。密钥仅保存在本机，不回显、不写入项目；编辑时留空保留，
修改地址必须重填密钥。正在使用的配置须先切换后删除；旧识图配置自动映射为「识图 API」。
自定义配置的模型名称须填写服务商提供的准确模型 ID，不能由 API Key 推断；
修改生图来源或配置后，重新打开图片参数面板读取最新选项。保存设置不会发起生图。
生图方式对画布单图、变体、分组和 CLI run 统一生效，默认 Maker MCP。自定义 API 使用
OpenAI 兼容图片协议：无参考图调用 /images/generations，有参考图调用 /images/edits，
按原顺序上传 image[]；接收 data[0].b64_json 或 HTTPS 图片 URL。只支持这一种协议，
透明素材请求会向两种接口发送 background=transparent，需要所选模型支持透明输出。
不自动探测、回退或重试付费请求。标准尺寸直接传 size，其它比例用 auto 并在提示词声明目标尺寸，
结果沿用实际图片尺寸检查，不保证模型严格输出指定像素。下载失败恢复原图片，不重新生图。
图片卡的 Maker 模型选项来自当前项目 MCP 工具发现，按实际 generate_image/edit_image 操作读取枚举；“自动”沿用服务默认，参数始终为工具模型 ID。服务模型说明直接显示上游元数据，不维护版本名称映射。自定义 API 只显示当前生图配置名与实际模型，不发送隐藏的 Maker 模型；本地来源显示当前 AI 客户端、仅 CLI 生图导入。模型信息读取失败、旧模型不再支持或来源变化时阻止提交并提示重新确认，不切换提供方。Image3 当前上游仅用文字声明总共最多 3 张输入图，宿主据此限制；其它能力仍以上游服务为准。
识图使用所选配置的模型，GPT-6.1 Sol 保持 low，其它模型不强加思考档位。默认 Server API，按当前项目只读检查接口可用性；不可用时置灰并提示恢复接口，不切换渠道。旧本地 AI / 网页来源读取时按 Server API 生效，保留旧配置文件；自定义 API 保持不变。
图片卡「识别 UI」使用所选 API；接口不可用时提示错误。已有任务仍可查询，已有结果仍可查看标注。
生图方式中的本地模型仅限 CLI 客户端自身执行；画布直接运行会提示，不能唤起客户端或偷偷改用 Maker。
`taptap-maker canvas model-settings --target-dir <项目>` 返回当前有效来源并只读检查 Server API，不返回密钥。省略项目时不发远端请求，Server API 按不可用处理；`vision.selectedSource` 保留原选择，`vision.source` 为有效来源。
本地结果可用现有 canvas import 新增图片卡；它不是模板节点回填接口，不代表原工作流已完成。
保存设置不调用模型。去文字卡的「运行两次识图」先提取图片 UI，再从原稿提取文本，
结果可导出固定 Bbox JSON；契约与恢复方式见 [Maker UI 工作流](MAKER_UI_WORKFLOW.md#元素识图与-bbox-json)。

“构建与测试”分别显示本机全部项目预览占用、当前项目占用和分类，可展开项目明细。
缓存面板位于日志下方、任务历史上方。
范围包含整个 Maker home 的 preview 目录（含旧副本、未归属目录和状态文件）、
已登记或由历史记录识别的项目内 .maker-preview，以及 Windows 已标记的临时下载缓存。
不扫描整个磁盘寻找已移走或未登记的项目；不含原项目源码、正式 dist、独立安装的共享 Runtime。
进入页面统计一次，支持手动刷新；无法读取或链接目标被跳过时标明统计不完整。
统计采用异步文件遍历，不随心跳反复扫描；数值为文件字节数，不代表文件系统独占物理空间。
“清理当前项目”和“清理全部项目”二次确认后清理已结束且不再被进程持有的验证记录、
普通预览会话副本、独立准备副本、公共索引及项目内固定副本。
复用项目操作锁、同源校验及归属核验；预览或 Runtime 状态未知时保留对应项目并提示。
活跃验证、异常记录及清理未确认的准备副本保留并提示。Runtime 下载资源单独显示但不清理，
不触及原项目源码、Runtime 安装、外部归档以及 Windows 临时目录中的下载缓存。
未知归属内容计入总量但不自动删除；统计大小不等于本次可清理大小。
验证自动保留每项目最近 3 次已结束记录；正在运行或退出状态不明的记录额外保留。

Lua LSP/Python 状态在后台异步检查，同一时刻只执行一次；首次返回“检测中”，
后续复用 30 秒缓存。检查不得阻塞状态、停止或健康请求；关闭控制台时取消并等待检查进程退出。

控制台是 Maker CLI 的本机网页入口，随包分发，无需安装前端开发环境。

## 其他 / UI 动效与项目检查

“其他”是独立的控制台页面，支持 ?page=other 直达，默认打开“UI 动效”，左侧依次为“项目检查”和“UI 动效”。
内部切换不修改顶部主导航；离开“其他”后整个工具区隐藏。
UI 动效随 Maker 包分发，由同源的 /ui-motion 页面承载，无需选择项目或运行额外演示服务器。
“NanoVG 绘制”排在第一位并默认展示，包含五个完整界面与三个转场的大卡片；默认呈现随包示例，不依赖本机参考目录。
动效必须使用原版 LuaTween，不使用 JS 移植或自写缓动。网页通过 Fengari 执行 LuaTween 与共享 Lua 配方，
Canvas2D / NanoVG 只绘图；内置简化候选、完整界面、图片 UI 和 43 项工坊均采用这一约束。
默认使用随包的 Lua、UI.json、时间线与资源索引；PNG、字体按示例资源机制下载校验并缓存，
无需本机参考项目。`/ui-motion/runtime-reference` 返回实际执行的 Lua、接入说明和资源地址。
页签上方用两行介绍 LuaTween；“源码”和“使用说明”在当前页只读弹窗展示随包的 LuaTween.lua
与 README，不跳转外部仓库，下载的离线示例也可直接阅读。用户体验后点击
“选用 · 交给 AI → 复制接入指令”，指令记录当前效果、皮肤或片段，而非最初打开的卡片。
AI 默认只将所选动效接入已有 UI：复用项目已有的兼容 LuaTween；未安装时放入
`scripts/LuaTween.lua`，沿用项目统一更新入口与组件生命周期，不要求用户手动安装。
`taptap-maker-local` 的 `references/ui-motion.md` 与参考包内 `docs/LuaTween-integration.md`
共用接入指引。参考包同时包含库 README、API、版本和 SHA-256；下载后可交给另一台电脑的
AI，官方素材使用稳定 CDN 地址。仅明确要求整套示例时才导入相应图片与布局。
原生入口保留独立生命周期，只有调用者自己的控制器会被销毁；逐帧定位不执行业务回调。
参考项目另有 `ui-motion-vector-sample/index.html` 时，仍可指定本机素材覆盖；运行代码由当前包提供。
同目录的 `catalog.json` 可列出完整界面与转场卡片，替代内置矢量卡片；未提供清单时仍展示单张样板。
随包参考包含可编辑 UI.json、独立 PNG 与原生入口，AI 接入指令指向当前包实际执行的源码。
本机示例的体验弹窗随窗口高度布局，嵌入页通过 `embed=1` 调整画面与关键帧区域；轨道较多时在时间轴内滚动。
转场卡片的演示播完后保留所选转场，支持重播、逐帧定位和进入目标界面；游戏内按钮仍按正常流程切页。
`/ui-motion/vector-sample` 默认呈现随包示例；本机覆盖只保留素材和布局，使用当前包 LuaTween 播放。网页与游戏 NanoVG 入口分别标明。
“NanoVG 绘制”底部提供“更多动效”，在控制台内打开随包工坊。
该工坊按六类提供 36 组动效与 7 种按钮反馈，支持七套按视觉关键词命名的 UI 风格、组件点击、重播和 33 项顺播。
界面仅展示普通 UI 组件和必要操作符号，不包含角色、怪物、游戏专属标记或特色道具插图。
左侧展示按钮、弹窗、列表、物品、对话与奖励，右侧目录可滚动；保持横屏画面，不显示底部时间轴。
风格通过左右小三角循环切换，底部当前名称可展开七套界面列表，支持上下滚动与键盘选择。
首次打开及切换皮肤显示 loading、字体准备和真实图片计数；加载期间禁用选用，
失败提供手动重试，连续 60 秒无进展提示超时，不自动重试或修改 LuaTween 动效配方。
组件皮肤使用 NanoVG 与按风格分类的独立 PNG；按各自设计稿保留布局与材质，
面板、控件、列表行和物品卡独立绘制，坐标及层级见参考项目的 assets/ui/motion-lab-v2/。
阶段时序保留在 catalog.json 供 AI 接入参考。
网页通过 Lua VM 与 Canvas2D 执行同一份动效 Lua；原生入口为 `scripts/MotionLabMain.lua`。
目录切换清理舞台效果并中断顺播，弹层遮罩不阻挡外部目录；定位后通过重播回到交互。
径向菜单、弹性回弹与磁铁拖拽标注为自动演示；游戏业务与真实拖拽由接入方实现。
`/ui-motion/motion-lab` 仅只读提供固定文件，沿用本机示例的路径、大小与 CSP 限制；
工坊文件上限为 48 MiB，其余本机示例仍为 24 MiB。
未指定本机参考目录时使用随包工坊；显式指定的目录缺少该文件时不展示工坊入口。AI 指令以当前包实际源码为准。
“图片 UI”展示五个游戏项目界面（主菜单、角色选择、剧情对话、绒幕星仪剧场、章节剧场）与三个转场，
使用已审核原创设计经 Maker 画布生成/分离的独立 PNG、可编辑 UI.json、原生 Lua 及其导出的时间线。
当前通过 UI 组件的 `backgroundImage` 绘制图片；图集帧与序列帧动画可使用引擎 `UI.Sprite`。
四名角色可切换立绘与属性，VELA 提供六段独立生成的攻击姿态；剧院两页通过星仪扑克牌衔接。
通过 TAPTAP_MAKER_UI_MOTION_REFERENCE_DIR 指定参考游戏项目根目录，
该目录应含 ui-motion-native/catalog.json；控制台仅只读提供清单中列出的预览文件、PNG、UI.json、Lua 和字体。
清单上限 1 MiB，文件和图片列表各最多 1024 项；参考包文本累计上限 32 MiB，
单文件读取上限 24 MiB。超限清单不接入；参考包正文及文件超限时在读取正文前返回 413。
已审核的官方素材经授权登记示例资源库，图片无损压缩并校验 CDN；字体保留许可证。
本机覆盖仍只读，不自动上传用户自定义素材。未配置目录时展示官方图片 UI，不用矢量候选替换。
动效库不加载或提供视频、整屏原片抽帧、原帧人物序列；素材路由仅允许实际使用的独立图片和字体，
旧 web-demo / web-demo-clockwork 研究目录不再接入；未列入新清单的文件返回 404，媒体播放由 CSP 禁止。
卡片预览取同一套 PNG 与 UI.json 的静态渲染；人物动作使用独立生成的姿态图，不包含原片人物序列。
图片 UI 卡片显示排队、加载及失败状态，进入页签后仅将靠近可见区域的卡片加入预览队列；失败可单独重试，

本机参考覆盖也使用当前包配套的播放器 HTML、CSS 和 JS，避免旧页面缺少加载控件；素材与游戏 UI 布局仍取本机文件。
GET /ui-motion/original-reference?id=S01 返回适配后的源码、独立素材路径和读取地址；
参考包包含精确文件清单、来源画布、UI 路径、脚本、素材 SHA-256 与未实现边界。接入层不改写游戏文件。
选用后的 AI 指令要求只使用清单中的独立素材，分别实现 UI、交互与动效。
演示中的“素材原图”展示同一清单的独立图片和字体，点击图片可打开原文件，不展示原片参考帧。
两套示例均采用大卡片，不再保留零散动效列表和底部选择栏。原版可直接操作既有界面控件，
并提供暂停、重播、调速和关键帧定位；“打开独立演示”读取同一份清单。人物动作采用二维姿态与实时光效，
其他角色提供技能反馈；地图、后续台词与章节业务由接入项目实现。嵌入页按可用高度等比缩放画面，保留关键帧操作区域。
离开页签、切后台或关闭演示时暂停，返回后手动继续。卡片页跟随控制台深浅色，原版保留自身配色。

不随包复制原片、角色素材或审片数据；原生渲染、美术精修和完整业务页面待后续确认。
演示不调用生成接口、不修改游戏项目，也未接入战斗、奖励、账号或存档。

NanoVG 仅绘制特效图形，输入与业务状态由宿主持有。网页播放通过不代表引擎实机验收。

“其他 → 项目检查”是一张纵向滚动的报告，共用顶部当前项目，不再拆分内部功能页签。
有两种检查：自动检查与 AI 检查。内置 maker-project-check Skill 指导 AI 读取源码并通过 CLI 保存结果。
自动检查由页面触发：当前项目没有检查结果时，首次打开检查页自动执行一次（每个项目每个页面会话一次，
失败后不循环重试，显示“重新检查”）；已有结果时工具栏“重新检查”手动触发。它走
POST /api/projects/:key/project-check/run，只读扫描源码与素材（不调用 AI、不联网、不修改项目文件，
结果写入 Maker home），按目录给 Lua 脚本分组，报告标记 analysis.auto 并显示“自动检查 · 模块按目录分组”。
同一项目并发请求共用一次运行；项目已存在 AI 分析结果时，服务端要求 replace:true，页面先弹确认，
避免静默覆盖模块职责说明和整理建议。检查期间显示加载状态与已用时间。
自动检查固定扫描前确认的报告版本；扫描期间有新报告发布时拒绝覆盖，保留新报告。
AI 检查由用户通过 AI 对话发起，空状态与工具栏“让 AI 更新”提供可复制指令；完成后重新打开检查页读取最新快照。

CLI 提供 project-check capabilities / collect / publish / show。
collect 收集素材与源码事实，返回 factsRevision 和当前 resultRevision；AI 阅读实际代码后
填写模块职责、源码导览、可选业务流程、素材结论和未核实项，publish 校验后保存。
show 只读最近结果。collect 不覆盖已发布结果；版本冲突、路径/行号无效或已收集源码变化
会拒绝 publish，保留原结果。JSON 契约和上限以 capabilities 为准。
结果按项目 realpath 与 project_id 隔离，保存在 Maker home/project-checks，不写游戏目录。
CLI 与控制台必须使用同一 Maker home；保存使用跨进程锁与私有 JSON 原子替换。
保存复用 UI 动态端口锁核对持有者，确认进程退出后回收；旧版无归属记录的锁保留并提示人工核实。
结果显示采集和生成时间，不代表后续项目修改已复核。

素材事实覆盖 assets、scripts、项目根 Lua、.project、.maker/canvases、.maker/ui-workflows
及 .maker/assets/generated-assets.json，展示静态引用候选、
SHA-256 完全相同副本、PNG/JPEG/WebP 大图、目录直接文件数与体积。
路径、文件名和 UUID 仅是引用线索；动态加载、二进制依赖、自定义目录和构建规则由 AI 复核。
长边 >2048 为中高风险，>4096 为高风险；RGBA 估算不等于实测内存。
大量素材堆在 assets/image 只提示核对，目录分类结合用途区分运行素材、创作原稿与历史资料。

edges 和 nativeMenuInset 参与布局，背景不受影响；绝对定位控件应放在安全区内的普通布局容器中。
拖动和缩放沿用原锚点、百分比及 aspectRatio；flex 节点保持原定位方式，不自动改成 absolute。
参考图对照随当前逻辑视口显示；像素对位应先选择组装记录的逻辑参考尺寸及缩放 1。
浏览器预览不执行游戏 Lua，不能代替真实引擎的字体、动态内容及真机验证。

顶部「适配检查」把当前（含未保存修改的）文档依次放到标准手机 16:9、iPhone 18 Pro、iPad Pro 13 英寸各排一遍。
检查会先等待各屏幕所需的项目字体，再生成结果和缩略图；字体加载失败时，弹窗和「复制给 AI」均注明使用了备用字体。
只检查游戏本身的方向：文档设计尺寸有宽高时按宽高判断，否则取项目设置的屏幕方向（`screen_orientation`），
与顶栏临时切换的横竖屏无关；两者都没有时才横竖都查，并在弹窗里说明。弹窗上方是每块屏幕的缩略图（红色轮廓标出问题位置，淡红区域为模拟安全区），
下方按严重程度列出问题，名称仅数字不同的节点（如 item_1…item_40）合并为一条。
检查项：按钮、文字、图片被屏幕边缘裁切（问题）；整个控件在屏幕外、被 overflow 父容器截掉、
进入安全区、文字比控件宽或高（警告）；按钮触控区折算后低于 40 pt（提示，默认收起）。
滚动列表内的内容靠滚动露出，不按屏幕裁切判断；铺满屏幕的背景图不检查。
点击缩略图切换到该屏幕，点击问题行切换到首个受影响的屏幕并选中全部相关节点，「复制给 AI」输出同样内容的 Markdown。
检查不修改文档、撤销记录和选择，结束后恢复当前设备与滚动位置；组件需勾选“在屏幕中预览组件”后才可检查。
结果是编辑器模拟，字体、动态数据和安全区数值与真机、引擎可能不同。

### UI 文档 CLI

同包 CLI 提供 taptap-maker ui，使用 ui capabilities 查看操作格式。
list/inspect/create/patch/check 直接操作已绑定项目的保存文件，不需要浏览器或控制台进程。
preview/layout 使用下文的编辑器渲染连接；open 获取或打开编辑器地址。
每次明确传入项目绝对路径；文档路径相对项目根且必须为 assets 内的 .ui.json。

```sh
taptap-maker ui list --target-dir /absolute/project --json
taptap-maker ui inspect --target-dir /absolute/project --file assets/ui/main.ui.json --json
taptap-maker ui inspect --target-dir /absolute/project --file assets/ui/main.ui.json --id title --json
taptap-maker ui create --target-dir /absolute/project --file assets/ui/new.ui.json --input-file document.json --json
taptap-maker ui patch --target-dir /absolute/project --file assets/ui/main.ui.json --revision SHA256_FROM_INSPECT --input-file changes.json --dry-run --json
taptap-maker ui check --target-dir /absolute/project --file assets/ui/main.ui.json --json
taptap-maker ui open --target-dir /absolute/project --file assets/ui/main.ui.json --no-open --json
```

create 输入完整 UI 根节点，自动建立缺少的目录，已有文档拒绝覆盖。
inspect 返回文档 SHA-256 revision 和节点树；可用 --id 或 --pointer /children/0 缩小读取范围，
revision 始终对应整个保存文件。无 ID 的节点可用 pointer 定位，空 pointer 表示根。
patch 输入一个批次，例如：

```json
{
  "operations": [
    { "op": "set", "id": "title", "props": { "text": "新的标题", "left": 24 }, "unset": ["right"] },
    {
      "op": "add",
      "parentId": "screen",
      "node": { "type": "Label", "id": "hint", "text": "提示" }
    },
    { "op": "move", "id": "hint", "parentId": "screen", "index": 0 },
    { "op": "remove", "id": "obsolete" }
  ]
}
```

set 可修改文字、位置、尺寸、资源引用等声明属性，不能直接替换 children 或内部字段。
remove 删除节点及其子树；根节点不能删除或移动。
add/move 的 parentId 可改为 parentPointer，省略父级时使用根节点。
index 表示目标 children 中的位置，省略则放末尾；同父级移动按移除后的数组计数。
move 保留节点的局部坐标和布局属性；跨父级需要保留视觉位置时，在同批次中显式 set 新坐标。
批次最多 100 个操作，任一步失败均不落盘；整批通过共享 UI 检查后只保存一次。

create/patch 支持 --dry-run，仅检查结果而不写文件或建目录；去掉此参数才执行。
输入可以用 --input-file 或 --input，二者互斥。检查包含默认与按下图片引用，仍不证明运行时、
字体和图片解码结果。业务错误、检查错误和版本冲突均以非零退出码报告；--json 输出结构化结果。

CLI 与网页复用同一保存锁、路径校验和原文比较，旧 revision 不会覆盖新版本。
CLI 不读取或改写网页未保存的草稿；CLI 写入后，在编辑器文档菜单选择「重新从磁盘加载」，
或通过 ui open 打开保存版本。旧网页草稿直接保存时会报告冲突，须保留草稿并合并。
open 返回带项目和 checkout 身份的控制台地址；不带 --no-open 时使用系统浏览器打开。
这些命令不自动生成 meta、不导入外部图片、不改 Lua、不构建或发布游戏。

### UI 预览与布局 CLI

首次用 ui open --no-open 获取地址，在浏览器打开该项目的 UI 编辑器并保持连接。
之后直接用 CLI 切设备、查询布局或输出干净 PNG，不需要逐次点击编辑器控件：

```sh
taptap-maker ui layout --target-dir /absolute/project --file assets/ui/main.ui.json --device iphone18 --json
taptap-maker ui preview --target-dir /absolute/project --file assets/ui/main.ui.json --device ipadpro --orientation landscape --output-file /absolute/preview.png --json
taptap-maker ui layout --target-dir /absolute/project --file assets/ui/main.ui.json --width 2520 --height 1080 --id close --json
```

- 设备 ID：720p、1080p（默认）、2k、4k、iphone18、ipadpro，与编辑器共用配置。
  自定义 width/height 必须成对，按给定宽高原样使用；预设方向用 portrait/landscape。
  未指定方向时与编辑器一致：按页面设计宽高判断，否则取项目 screen_orientation；均未指定时用竖屏。
- 高级参数使用 --input 或 --input-file：例如
  `{"device":"iphone18","safeArea":{"top":186,"bottom":102},"nativeMenuBottom":240,"dpr":3}`。
  可指定 scale 覆盖 UI 缩放；尺寸和安全区均为物理像素。设备安全区只是可编辑模拟值。
- 组件默认按自身尺寸渲染；加 --component-preview 后放到指定设备屏幕中居中预览。
- 两个命令均返回保存文件的 revision、物理/逻辑视口、实际 Yoga 布局、变换后边界和警告。
  layout/visualBounds 为逻辑单位，physicalBounds 为物理像素；布局坐标相对整个逻辑画幅。
  --id/--pointer 定位保存树中的节点；结果 pointer 指向展开后的预览树，不直接用于 patch。
- preview 不带 --output-file 时写入 Maker home/ui-previews 缓存；指定路径必须是已存在目录内的
  绝对 PNG 路径，不覆盖已有文件。不导出设备框、选中框或安全区辅助线，默认不写游戏 assets。
- 使用独立渲染页面，复用编辑器 Yoga、组件/模板展开、绘图及资源加载；不会切换当前文档、
  改变当前设备或读取/覆盖未保存草稿。不是无浏览器执行，断开页面后会报错或超时。
- 预览会等待图片加载完成，缺图/缺组件显式给出警告；动态数据、字体及引擎差异仍需游戏内复核。
  根文档使用提交时快照，依赖素材使用渲染时的保存版本。PNG 每边最多 4096 像素。

### NanoVG 图层

编辑器支持 `type: "NanoVG"` 图层，与普通节点共用选择、移动、缩放、层级、复制、撤销和保存。
节点树的类型名按组件着色：Panel 灰蓝、Label 金黄、Button 绿色、Image 珊瑚色、NanoVG 青色。
节点名称在深色主题下默认白色，未保存修改显示蓝色，保存成功或撤销至保存状态后恢复；
浅色主题使用深色对应色。标记基于保存快照，包含节点属性和层级变化，保存期间的新修改仍保留蓝色。
添加菜单选择「矢量图 NanoVG」；属性面板可修改透明度、绘图坐标范围和绘制指令，
点击「应用」前校验指令，错误不会替换原数据。CLI ui create/patch/check 使用同一格式和规则。

图层的 viewBox: [x, y, width, height] 定义局部绘图坐标，commands 保存白名单绘制指令；
调整节点宽高会缩放整层，不改曲线控制点。支持直线、贝塞尔曲线、圆角矩形、圆/椭圆、
弧线、填充/描边、线性/径向渐变、图片画刷、文字、变换及裁剪。具体操作和参数签名以
ui capabilities --json 的 nanovg.commands 为准。不接受脚本字符串或任意代码执行。
图片画刷的资源路径也参与项目资源检查。填充规则中的孔洞、箱形渐变、混合模式、字体模糊、
reset 类调用尚未支持，捕获或检查会报错，不静默丢弃。textBox 支持多行文字和显式换行；
浏览器字体与原生字体不同可能导致换行位置和行距差异，需按实际字体复核。

Lua 自绘逻辑不能直接作为普通 Panel 导入。随包 MakerNanoVG.lua 可显式捕获命名绘图层，
也可回放保存后的数据；ui nanovg-adapter 输出源码，--json 输出带 source 的对象，
命令本身不修改项目。使用引擎 UI.LoadJSON 时须先注册 NanoVG 控件，原始 nvg 绘图项目可
直接回放图层，详见 [NanoVG 提取与回放](../skills/lua-ui-to-json/references/nanovg.md)。

浏览器使用 Canvas 2D 预览绘制数据，字体度量、抗锯齿、非等比描边和旋转裁剪与原生 NanoVG
可能有差异。捕获表示调用当时的视觉状态；游戏事件、存档数据、动画和点击热区仍在 Lua。
图层移动不会自动重写游戏热区。原项目不会因打开编辑器而安装适配器或替换游戏入口。

实现位于 src/maker/uiEditor/，由原 UrhoxUIEditor 代码迁入并在本仓库维护。
浏览器代码和 Yoga WASM在构建时嵌入 dist/maker.js，npm/客户端插件随同一 bundle 分发。
官方画布模板媒体按需下载：已校验的本地缓存优先，其次 CDN，失败尝试 GitHub，
通过大小和 SHA-256 校验后缓存；项目自己的图片不受影响。首次使用未缓存的示例需要联网。
添加模板直接引用公共缓存，不复制示例到用户项目。画布制作中的图片保存在
.maker/canvases/images/；用户导出时选择位置，015 最后自动交付游戏素材并拼装 UI。
Maker MCP 内置生成接口的默认落盘保持原样。
不依赖个人仓库、Python 或额外端口。原项目 MIT 及 Yoga 许可证保留在 web/ 内。
资源维护、无损压缩及发布顺序见仓库的 [示例资源维护](https://github.com/taptap/instant-games-open-mcp/blob/main/docs/MAKER_DEMO_RESOURCES.md)。
文件接口绑定登记项目 realpath，只读受限类型/大小的 assets 文件；拒绝符号链接、跨源写入和越界路径。
保存串行互斥并原子替换，前后检查原文；这不是对任意外部编辑器的跨进程事务锁。
编辑器独立 CSP 仅开放本机脚本和 WASM，不扩大控制台或画布脚本权限。

验证：npx jest --runInBand src/**tests**/makerUiEditor.test.ts；
node scripts/test-maker-ui-editor.mjs（Playwright 可用时）。

所有页签的控制台标题和导航默认采用紧凑布局，切页不改变顶部尺寸；画布名称在顶部页签展示，当前页签的
铅笔按钮用于改名。添加节点、模板、保存和更多操作位于画布左侧悬浮图标条，不占画布宽度，
悬停可查看名称及保存状态。

主题统一通过浏览器接口 `window.MakerConsole.getTheme()` 获取（`dark` / `light`），
`setTheme(theme)` 修改并持久化；`onThemeChange(listener)` 订阅变化，返回取消订阅函数。
存储受限时仍切换本页主题，`setTheme` 返回 false，控制台提示无法保存；非法主题值不生效。
同时派发 `window` 上的 `maker-console:theme` CustomEvent，`detail` 为 `{protocolVersion:1, theme}`。
自由画布和 UI 编辑器初次加载读取宿主主题，隐藏期间仍同步，切换不重载页面或丢失草稿。
独立打开时读取同一存储项，并响应其它窗口的存储变更；外部插件继续使用原 postMessage 协议。
主题只改变编辑工具外观，不改变素材像素、游戏 UI 配色或导出文件。
控制台与 UI 编辑器共用 webTheme.ts 的色板；编辑器通过 /console-theme.css 加载，
只映射面板等局部变量，不另定义强调色。普通按钮为中性色，保存和工具选中态使用青绿色，
复选框、单选框与滑杆统一使用青绿色，文字强调、焦点和列表选中态适配深浅色；警告状态保留警示色。

模板库每个模板的「添加」旁提供「预览」：在独立弹窗中按真实布局展示卡片、图片和连线，
支持全景、缩放、平移及铺满窗口。卡片不可编辑或执行；关闭后保留模板库筛选，
不向当前画布添加内容、不导入项目素材。未生成的步骤显示卡片标题，图片缺失时保留流程。
添加静态生图模板保留真实示例预览，首图可直接使用，下游从待处理开始，不把示例当作本次制作完成。

图片变体与扩展画面保留显式编辑提示词，不追加新建生图的通用素材约束，避免与保留按钮底板、

短编辑期间阻止页面输入，长任务继续使用现有任务保护和停止入口。
领取过的命令不重新派发；结果单独确认，断线标记 unknown，刷新不恢复付费任务。

同一页面保持单个普通操作，并为 inspect、stop 各保留一个独立在途位置；其他页面不受其历史数量影响。
wait 是有界状态查询，不是新调度器或反调 AI。用法与首版限制见画布目录 README。

## Stdio 代理进程与清理

更新 CLI 后，旧控制台进程仍保留原代码。console status 返回控制台与本次 CLI 的版本、入口和
启动身份，控制台另含 PID/启动时间；旧记录没有的字段为 null，不按当前磁盘内容猜测。
身份不一致时继续拒绝连接，并提示双方身份：先保存原画布，确认可以关闭后执行 console stop，
再用指定入口执行 console open --target-dir <项目>。不会自动重启或接管未保存修改。
验收本机源码时必须使用用户指定的 Node + maker.js 入口；Shell CLI 与会话 MCP 是独立连接，
插件的 doctor 结果不能替代本机产物身份。不必每次普通使用都采集整套哈希。

控制台使用的本地 stdio 代理统一通过 HiddenStdioClientTransport 启动，Windows 设置
windowsHide:true、shell:false，避免无控制台的 Node 宿主拉起可见命令行窗口。
stderr 始终排空；它是实时诊断流，订阅者接收后续日志，不缓存无人订阅时的历史，
避免常驻代理因日志积压发生背压。协议输出仍只从 stdout 解析。

直属子进程 exit 时立即通知 MCP 连接关闭，结束请求和背压发送，并自动清理 transport。
管理器也显式持有并关闭 transport，不依赖 SDK 在连接关闭后继续保留它。
常驻和短命 CLI 代理的失败请求都通过公开 AbortSignal 释放 SDK 的剩余超时计时器，
包括初始化握手；外部取消信号仍生效，不直接访问 SDK 私有状态。
下一次操作可创建新连接；已提交的生成结果未知时不自动重放付费请求。

关闭先结束 stdin 并等待最多 2 秒，再通过创建时持有的 ChildProcess 句柄发送 SIGTERM
并等待最多 2 秒；POSIX 必要时再发送 SIGKILL 并等待最多 2 秒。
Windows 已退出时立即释放本地管道；POSIX 在退出后最多再等待 2 秒排空继承管道。
并发关闭共同等待同一次清理，清理失败保留登记以便重试；未确认直属进程退出时明确报错。
启动失败也清理资源，关闭后的 transport 不复用，重连创建新实例。

这些保证只覆盖直属子进程与本地资源。释放管道不证明孙进程已回收；禁止通过旧 PID 执行
taskkill /T，也不添加 Job Object 或 PowerShell 进程树清理代理。

控制台关闭时先停止接收新操作并等待已有任务，再独立清理代理和预览。某项失败不阻断
另一项收尾；成功项不重复清理，失败项等待显式重试，不启动后台重试循环。失败记录脱敏写入
生命周期日志，并通过健康查询和 `console status` 返回；只保留健康查询和同源关闭重试入口，
所有权锁及退出信号处理保留到全部清理成功。运行 `console stop` 可再次尝试关闭。
`console stop` 返回 `running:true, draining:true` 只表示关闭请求已接受，不表示进程已经退出。
全部清理成功后才关闭 HTTP 并释放会话；打开控制台遇到清理失败时明确提示重试关闭。

页脚版本信息旁保留小号、低对比度中性色“独立游戏开发日签”入口；控制台先在后台加载外部 iframe，
只有收到 iframe load 事件后才显示入口，加载未完成或失败时不显示入口。
弹出区域只显示内嵌日签内容。
使用固定尺寸并根据可用空间缩放，深浅色随控制台切换。
不代理外部页面、不注入脚本；跨源隔离，不传项目数据或凭证，并使用 no-referrer。
不允许弹窗或顶层导航。鼠标离开后延迟关闭；日签加载失败不影响控制台连接。

项目根 README/AGENTS/CLAUDE、docs、engine-docs、urhox-libs、examples、templates，
以及 `.installer/skills`、`skills` 和常见 AI 客户端目录中的 Skill 资料。
同一真实文件去重，不扫描隐藏计划、凭证、node_modules 或项目外链接目录。

代码块保留原文；不把解码结果作为 HTML 渲染。此入口仅阅读，不安装或执行 Skill，不新增 MCP tool。

`maker://` URI，便于粘贴给本机 AI 客户端；不复制控制台 URL 或访问凭证。

构建与测试页在操作区下方提供通栏日志区，按构建、Lua 检查、Runtime 分页签查看，
支持刷新、复制及自动换行。上方仅展示简短状态；日志按项目隔离，后台刷新不切换所选日志。

控制台和 Agent preview run 的最终证据显示最近最多 100 行、64 KiB 日志，避免启动日志挤掉
游戏输出；截断会明确提示。CLI preview logs 默认仍从开头分页，--tail 可读取末尾，
--cursor 配合 session/reload 标识可继续增量读取；不把日志或窗口存活当成游戏断言通过。
日志栏提供“清理日志”，只清空当前项目、当前页签的显示，不删除日志文件、不停止任务；
页面刷新后可重新读取原日志。任务历史按项目只保留最近 10 次，启动时也裁剪已有历史，
超出记录从存储和界面移除，执行中的任务不提前丢弃。
生成二维码、启动或刷新本地预览、Runtime 安装、Lua 检查和远端构建等耗时操作会在按钮上显示
loading 并禁止重复触发；二维码任务提交后立即打开等待弹窗，完成后替换为二维码或明确提示失败。
构建进度条继续展示真实阶段进度，与按钮 loading 分开。

### Validate 过程记录

日志区的 Validate 页签展示当前项目通过 `preview validate` 留下的本地证据，不发起验证任务，
不推送控制指令，不要求控制台先运行。多轮记录按时间倒序列在同一可滚动区域，最新结果在最上面，不用下拉框选择；
首次读取最近 20 轮，滚动到底部或点击底部“加载更早记录”继续读取历史，已加载轮次不会被新记录替换。
每轮包含实际调用参数、准备日志、stdout/stderr/Lua 合并日志、原始 JSON 报告和截图；
收集完成不等于游戏 PASS。内容以准备日志、运行日志、截图和原始 JSON 分块展示，
日志与 JSON 默认缩起并显示末尾最多 3 行缩略内容；展开查看完整的有界内容，
长日志在卡片内滚动，不撑长页面。截图始终显示小图，最大 240×150 CSS 像素。
轮询保留展开状态和日志滚动位置；在顶部阅读时保持显示最新结果，向下查看历史时不抢走位置。
图片按浏览器可见范围懒加载，点击可查看原图；无截图明确区分未请求、等待采集与未收集到，
读取失败可单独重载图片，不重新执行验证。
只在构建页的 Validate 页签可见时约每 5 秒刷新，运行日志按各轮独立游标增量读取。
历史摘要刷新和翻页不等待整批证据读取；证据仍限制并发，避免占满本地读取名额。
已完成且未变化的证据与轮次卡片复用页面缓存，仍有未读日志或读取错误时继续获取。
切换项目保留各自历史、展开状态和滚动位置，旧项目迟到的响应不会覆盖新项目。
异常中断、缺少最终记录显示结果待确认，不把进程存在或截图文件存在当作验证成功。

控制台仅读取登记项目的固定证据文件；不接受任意本地路径，不跟随证据目录或文件链接，
日志和 JSON 脱敏后按文本展示。“清理日志”清空当前项目所有已加载轮次的证据显示，
不删除磁盘证据、不停止验证；清理后新增的运行日志仍可显示，截图可单独重载。
普通任务的最近 10 次历史限制不适用于 Validate：证据按项目 realpath 分隔，保留最近 3 次，
每轮结束清理超出次数的非活动记录，活跃或退出状态未知的记录额外保留。
不设后台定时任务，打开、关闭控制台或浏览记录均不触发清理。
超过 5 GiB 只告警，不删除近期记录。
长期验收使用 `preview validate --output-dir <绝对目录>`，详情见
[本地验证说明](MAKER_LOCAL_PREVIEW.md#本地多轮验证与过程可见性)。

本地预览启动、刷新、安装遇到异常，以及构建/二维码出现已识别的基础设施异常时，
当前项目会弹出一次简短的“提交问题反馈”确认。取消不上传；确认后在后台复用
`mcp report --context-stdin --consent`，不新增 MCP tool、不填写表单。
报告自动附带操作错误、系统/Node/Maker 版本和受管理预览日志尾部，凭证及用户主目录脱敏；
不读取浏览器传入路径，不上传项目源码。日志最多每份 6000 字节，缺失日志不阻止反馈。
标题分类由 `MAKER_ISSUE_CATEGORIES` 统一维护：`Maker MCP`、`控制台`、`UrhoX Runtime`、`构建`；
分类表示出错环节，不代表已确认根因。Lua 代码错误、已识别的登录/配置/交互问题不弹反馈。
同一页面会话内同类错误不重复弹窗，同一任务不重复提交；历史失败不在打开页面时集中弹窗。
任务历史展示提交状态及成功后的 Issue 链接；提交中禁止关闭服务，不改变原任务结果。
重启后未记录结果的反馈显示“结果未知”，不自动重发。自动上传依赖已安装并登录的 GitHub CLI
及网络可用；无法提交时明确提示，不把手动反馈草稿当作成功，也不新增登录流程。
预览启动前的状态检查若发生超时、5xx 或内部异常，也会记录为普通失败任务并复用同一反馈流程；
已知的配置、权限和状态提示不会误触发上报。反馈读取 Runtime 证据时必须匹配原任务的
`session_id` 与 `reload_id`，无法确认归属则不附带其它轮次日志。

项目与构建页的主操作行包含本地预览、构建、测试二维码；本地预览使用青绿色加粗，
Lua 检查开关和检查结果集中在构建页的远端构建区域。主导航旁展示分支与连接状态，
连接时间放在悬停提示中，不再单独占用状态栏。预览窗口设置默认折叠为方向、尺寸摘要，
展开后沿用现有设置与保存流程；运行中显示实际启动尺寸，并提示已保存但尚未应用的设置。
日志位于紧凑操作区下方，刷新、清理、复制使用带名称提示的图标按钮。
项目页最近任务展示最近 10 次摘要；成功任务的原始输出默认折叠，
二维码查看、Web 预览与开发者选择入口不依赖展开详情。运行中的任务及最新任务的失败、
未知结果默认展开诊断；更早的任务折叠但保留完整详情。Lua 检查失败仍以结构化检查摘要为主。
测试二维码复用现有远端生成流程，确认后执行。新项目缺配置时先提示构建初始化，不先收集无法保存的字段；
缺少名称、分类时可在确认框补齐，不要求手动编辑 JSON。补齐配置或首次选择方向后，
确认框明确告知会提交、推送当前项目的所有本地改动，复用 push 同步到服务端后再调用二维码工具，
由该工具构建上传，不额外执行一次远端 build；
同步失败时停止，不继续调用二维码工具。配置无需补齐时不提交本地改动。
任务启动前保存待同步标记；进程中断、控制台重启或结果过大时不丢失，重试仍需确认同步。
远端二维码工具自身会构建、上传测试版本，并在需要时创建 TapTap 应用，不等同于正式发布。
已有发布方向直接复用，首次缺失时必须手动选择，与预览窗口方向无关。
二维码任务按项目隔离，日志增加二维码页签；结果未知时不自动重试，再次生成前提示可能重复上传。
当前项目任务完成时自动显示约 400px 的白底二维码弹窗；历史结果通过“查看二维码”重开。
识别工具返回的 Markdown 图片链接或 MCP 图片内容；远程图片仅嵌入已确认的二维码 CDN，
未知地址仍保留结果链接。加载失败只重载图片，不重新调用二维码工具。其它项目完成不抢弹窗。
远端要求选择开发者身份时，任务提供“选择开发者并继续”入口，使用通用单选弹窗展示
远端返回的身份及 ID，不预选；当前任务首次返回该列表时直接弹出选择框。
取消不修改配置、不重试；明确确认后保存选择并沿用配置同步流程，
只继续生成测试二维码，不执行远端错误文本中建议的正式发布操作。
二维码确认同步时，若远端 `project.json` 仅有格式变化、本地仅修改二维码发布字段且该文件未暂存，
允许保留本地配置完成快进；真实内容冲突仍停止，不自动 stash 或覆盖工作区，普通构建规则不变。
弹窗只接入已识别的交互类型；其它错误仍显示原始诊断，不从任意报错文本执行命令。
配置中的开发者不可用时保留原 ID，明确提示先核实账号与开发者权限，不自动清空配置、选择身份或重试。
CLI 等价入口为 `taptap-maker qrcode --target-dir <PROJECT> --json`，首次方向通过
`--confirmed-screen-orientation landscape|portrait` 明确设置。需补齐时可传
`--confirmed-title <名称>`、`--confirmed-category <分类>`，并以 `--confirmed-build`
明确授权提交同步和工具内的构建上传；保留该参数名兼容旧调用，不额外执行 build。
不授权则不修改配置或执行同步。

标题旁的版本下拉框显示当前运行版本及最多 5 个可选版本，按版本号排序并保留有效的 latest / beta；同渠道有更新时青绿色提醒。
选择其他版本需二次确认，Beta 和降级会明确提示。控制台通过所选精确版本的现有
`upgrade --launcher self --json` 流程校验并更新客户端配置，不新增 MCP tool。
升级进程会显式定位本机 Node/npm/npx，不依赖图形界面继承的终端 PATH；npm 使用 Maker 专用可写缓存，
并在命令返回成功后核对目标版本的 `mcp-runtime/<version>/package.json` 与 `dist/maker.js` 已落盘。
安装完成后需重新连接 AI 客户端 MCP；当前控制台不会自动切换版本或中断预览。
插件渠道只显示当前版本，须通过对应插件市场更新。查询失败可在下拉框中重试。
更新任务保存在当前控制台进程中，执行期间禁止重复更新及主动关闭，不触发空闲退出。
更新异常不自动重试；部分客户端配置可能已更新，应检查后再决定是否重试。
升级超过 10 分钟时有界清理本次启动的进程并释放输出管道，结果标记为待确认；检查客户端配置及升级进程后，重新打开控制台才能再次升级。

## 使用

在游戏项目对话中说“打开控制台”，或运行：

```sh
taptap-maker console open --target-dir <游戏项目绝对路径>
taptap-maker console status --json
taptap-maker console stop --json
```

`open` 自动打开浏览器；加 `--no-open --json` 只返回地址。不指定项目时展示项目列表，
不自动选择。相同 Maker 版本从 Codex、WorkBuddy 或独立 CLI 重复打开时复用同一个用户级服务；
切换版本前先停止旧控制台。
仅支持本机访问，不支持局域网或 SSH 转发。地址只包含 loopback origin 和可选的项目定位参数；
控制台不使用访问 token，仍不要把本机地址当作远程入口分享。

- 项目列表登记已绑定的本地目录，不扫描磁盘。init/clone 成功后自动登记，
  点击项目行的“打开”后切换到该项目的“项目”页签；再次打开当前项目也进入该页。
  已有项目可点击“打开本地文件夹”，通过 macOS / Windows 系统窗口选择项目或父目录。
  仅在用户选择的目录中按 `.maker-mcp/config.json` 项目绑定校验并批量登记，重复项目跳过；
  不自动初始化、构建或切换项目。取消选择不修改登记；读取或校验失败显示汇总。
  Windows 选择窗口使用可见置顶父窗口；弹窗失败不视为控制台掉线。
  关闭或刷新请求页面时取消尚未完成的选择进程，释放选择状态；无交互桌面时明确提示原因。
  遇到有效项目不再深入其内容，跳过依赖目录及子目录符号链接；
  扫描最多 8 层、5000 个条目、200 个项目或 10 秒，达到限制会提示缩小选择范围。
  移除记录不删除游戏。
- 项目页顶部展示本机 Runtime 和独立 maker-lua-lsp 安装状态（是否安装、版本）。Runtime
  在 `~/.taptap-maker/runtime/` 登记并由所有项目共用，切换项目不会要求重复安装；旧项目级安装
  会自动登记为本机安装。Lua LSP 未安装不影响控制台连接。已安装 Runtime 时优先显示版本，
  没有版本时显示安装时间，未安装时可进入现有 Runtime 安装流程。
- 构建页提供独立“Lua 检查”按钮。控制台启动本机 maker-lua-lsp 的项目级 LSP MCP 会话，
  查询 textDocument/diagnostic 检查当前项目 scripts，不调用 --mode check，也不要求安装
  emmylua_check。诊断未完成、超时或结果不完整时记为检查不可用，不能显示为通过。
  构建按钮旁默认勾选“构建前检查 Lua”，
  勾选后先检查，发现 Lua 错误则停止提交和远端构建；取消勾选可直接构建。LSP 未安装时提示
  环境问题，不把安装缺失当成代码错误。勾选状态保存在本机浏览器。
- 项目页的构建和本地预览快捷操作会先切换到“构建与测试”。构建调用现有 CLI，可能提交并推送
  代码；页面显示真实阶段及该阶段的进度，没有有效比例时显示不定进度，不拼接虚假的总进度。
  Git 提交失败和服务端返回的错误默认展开，包含分类、命令、stderr 和下一步，不要求先打开
  任务详情。最近构建详情和 Runtime 日志使用整行宽度，结果未知时先核实，不自动重试。
- 任务运行时可以切换项目；任务和日志仍归属发起项目，同一项目的重复操作仍被拦截。
  切换页面不取消已发起的“Lua 检查 → 构建”流程。
- 顶部切换项目后，当前页签留在原地并刷新为对应游戏。页面用 `getCurrentProject()` 读取当前项目，
  用 `onProjectChange` 在切换时刷新自己。当前项目不可用、且该页必须有项目时，回到项目列表。
  文档页可以没有项目。插件工作区按项目保留，切换只显示对应工作区，不重新加载。
- 从顶部“本地预览”进入时，若缺少 Runtime，确认安装成功后继续启动原项目；
  独立“安装 Runtime”按钮仍只安装，安装失败或结果未知时不会自动启动。
- 本地预览的安装、启动和刷新见[预览指南](MAKER_LOCAL_PREVIEW.md)。
  新版启动未建立控制通道时，最长 30 秒后可重新检测并启动；不会一直因零 PID 启动记录置灰。
  旧版遗留且无法确认退出的启动记录会明确提示重启电脑后恢复，不要求用户手动删除文件。
  预览状态使用中文展示；Runtime 进程仍存活但日志出现资源等错误时，页面保持“运行中”并单独
  标记日志错误数量，用户可直接查看运行日志。会话 ID、Runtime PID 等技术字段收纳在折叠的
  诊断信息中，不占用主要状态区域。
- Lua 检查结果以构建页的检查摘要和问题列表为主；对应失败任务不自动展开，也不重复展示与
  结构化结果相同的原始输出。完整原始结果仍保留在折叠详情中供排查。
- Git 页展示提交关系、日期和差异；浅克隆的历史不完整，不提供分支切换或回退。
  「刷新本地历史」只读本地仓库。「拉取远端代码」只在 `main` 上、本地没有自己的提交、且文件不重叠时快进。
  已有本地提交或同一文件两边都改过时不改写历史；文件相交时弹出可复制给 AI 的提示词。
  不在 `main`、预览运行中、已有未完成的 Git 操作或远端不可用时，只在页面说明原因。
  拉取进行中占用该项目的控制台任务名额，其它任务和关闭控制台会等待它结束。
  快进不会被中途取消，避免留下 Git 锁。

### 配置与会话

在启动控制台的进程环境中显式设置 `FRAMECRATE_STUDIO_DIR`，指向已安装依赖并构建前端的
framepacker Studio 根目录绝对路径。控制台按项目打开内嵌标签，不弹出新窗口。
未配置或目录不完整时显示不可用原因；本轮不做安装器、ZIP 下载、插件市场或自动更新。

FrameCrate 子进程启动契约为：

```text
<process.execPath> --import <FRAMECRATE_STUDIO_DIR>/node_modules/tsx/dist/loader.mjs
  <FRAMECRATE_STUDIO_DIR>/server/main.ts --project <已校验的项目 realpath>
  --host-origin <控制台精确 loopback origin>
```

这是同一条命令，使用明确 Node、`shell: false` 和 Studio 根目录作为 `cwd`；
继承受信启动环境，不从游戏目录解析 Studio 模块，不触发生成、构建、提交或发布。
控制台由已安装的 dist/maker.js 运行时，把固定的自身 bundle 路径作为
FRAMECRATE_MAKER_ENTRY 交给 Studio，用于画布生图与视频能力；显式配置的
FRAMECRATE_MAKER_ENTRY 优先，不传 PAT，也不从游戏项目目录寻找可执行文件。
`--host-origin` 必须是当前控制台的精确本机 HTTP origin（含端口，无路径），
不能替换成通配符、另一端口或仅因同属 loopback 就信任的地址。

Studio 就绪 JSON 交付本机 URL 和匹配的 `projectPath`，URL fragment 使用 Studio 自有 token。
控制台仅将经校验地址交给对应 iframe，不传递 PAT；不将 token/URL 写入
任务历史、`/api/state` 或 MCP 配置。stderr 仅消费，不转发凭证。Studio 仍独立运行本地服务；
内嵌模式的 CSP `frame-ancestors` 仅允许 `--host-origin` 指定宿主，独立启动不开放被嵌入权限。

### 内嵌协议与生命周期

- 消息固定使用 `protocolVersion: 1`：宿主发送 `maker-console:connect`，
  主题变化发送 `maker-console:theme`，子页面回应 `maker-console:plugin-ready`，
  真实用户活动通知为 `maker-console:plugin-activity`。连接和主题消息携带 `light`/`dark`，
  插件跟随控制台主题且不维护独立主题状态。
  双方校验精确 `origin`、窗口 `source`、消息类型与版本，发送时指定目标 origin；
  消息不传 token，也不是生成、保存、任意命令或自动重试通道。
- iframe 使用 `sandbox="allow-scripts allow-same-origin allow-downloads allow-modals"`，
  不允许 popup 或 top navigation；保留本地导入、编辑、导出、工程保存恢复及完整 AI 工作流。
- 页面按项目与插件标识保留 iframe map，最多 8 个工作区。切换项目或标签只隐藏页面，
  不删除 DOM、不重写 `src`，不静默淘汰旧工作区。达到上限应拒绝新增并提示先保存。
  需要重连时由用户明确操作并提示可能丢失未保存编辑，不因超时自动重建 iframe。
- 同项目复用本控制台拥有的存活子进程；启动中或存活时不得被控制台自动空闲退出误杀。
  真实插件活动参与有界续期；插件轮询、握手和定时消息不能伪造用户活动。
  控制台宿主页自身通过有界页面租约保活，不能由 iframe 绕过宿主生命周期。
  最后一个子进程退出后恢复空闲计时；显式停止仅回收本实例启动的进程，不影响独立 Studio、
  IDE MCP 或 Runtime，也不等于取消已提交的远端视频。
- ready 子进程正常关闭等待 graceful drain，无强制超时；若它永久挂起，关闭会持续等待，
  这是避免截断写入的安全取舍，不承诺限时退出。未完成启动的回收仍可强制终止。

## 生命周期与恢复

服务自动分配空闲端口。控制台页面存活时每分钟续期，重新获得焦点或恢复可见时立即续期；
普通状态轮询只读取任务、项目列表和连接状态，不执行 Git，也不在预览空闲时探测预览。首次打开仍会加载一次当前项目详情。任务在心跳中结束时仍会刷新预览和构建详情。预览查询失败后最多再自动复查 2 次，已确认空闲则不再探测。健康检查不续期。页面关闭、浏览器退出或租约停止后，无任务时约 30 分钟退出，
任务结束后重新计时。关闭浏览器不会终止任务，`stop` 在任务执行中拒绝退出。
有预览任务或可核实存活的 Runtime 时，控制台拒绝主动退出；先停止预览。强制结束 Host 后仍应通过会话状态核对 Runtime，不按进程名清理。

`console open` 自动复用或用 Node 直接启动同版本控制台，不再要求用户手动启动 Host。
页面预览任务在控制台进程内调用共享预览业务，直接持有 Runtime；不经子 CLI 和独立 supervisor。
`preview start` 也通过相同的项目登记与任务接口发起，短命请求进程退出不停止用户游戏。
`preview run` 则由 Agent 前台 Node 直接持有 Runtime，调试结束清理自己的会话。
普通请求结束与整个 IDE 退出不同：外层 IDE 若回收整个进程树，预览也可能结束；不自动逃离其管理。
`console serve` 保留为可选外部终端入口，不是日常使用的前置步骤。
正常链路不使用 WMI、EncodedCommand 或额外安装的启动器，不要求关闭杀软。
控制台自身停止时等待其持有的预览收尾；按项目记录所有权，不因项目登记失效而遗漏活动进程。
新旧控制台协议不混用；升级后应先停止旧控制台再打开。
启动锁恢复使用短期 loopback socket 互斥，进程退出后由操作系统释放，不增加额外磁盘互斥锁。
已有 `.recovery` 文件仅在持有互斥且确认所属进程不存在时回收；空文件需超过 2 秒。
存活、权限不明或内容损坏的非空锁保持拒绝接管。首选互斥口 `EACCES` 时改试邻近口，
`EADDRINUSE` 视为互斥占用并拒绝接管；仍不探测、不关闭占用者。
升级测试前应结束旧版启动命令；旧版不参与 socket 互斥，无法保证与新版同时恢复空锁的安全性。
Windows 只有显式 `console open --legacy-wmi` 才运行旧 CIM 控制台启动器；
进入新版控制台后，预览仍由控制台直接持有。失败时不按进程名清理，不自动切换启动方式。
控制台有任务或自己持有的预览时不会空闲退出，界面显式关闭仍要求先停止预览。
断连后重新运行 `console open` 获取新会话地址，旧端口和凭证可能失效。
单次请求失败仅提示该操作错误，不停止状态轮询；同一有效会话恢复响应后自动恢复连接显示。
鉴权失败仍停止请求并提示重新打开。任何结果未知的修改操作都不自动重放。
网页不能自行启动已退出的 Node 服务，不设常驻唤醒进程。
任务历史和输出有上限，不作永久归档；异常退出时未完成的任务标为“结果待确认”。
Git 401/403 应检查凭证和项目权限，BLACKLISTED 需管理员解除账号限制。

## 维护约束

本地预览窗口设置通过项目绑定的 `/api/projects/:key/preview/window` 写入本机偏好，
复用 Origin 校验；项目任务执行中拒绝保存。方向支持跟随项目、横屏、竖屏，
无方向配置时默认横屏。提供 16:9、21:9、4:3 和可保存的自定义尺寸；不修改发布配置，
保存后仅在下次启动/刷新应用。详见 `MAKER_LOCAL_PREVIEW.md`。

启动或刷新本地预览前检查 Git 工作区中的服务端 Lua 改动（含暂存、新增、删除、重命名）。
识别 `entry@server` 入口及其专属子目录、`server` 目录/入口文件，以及 `.meta` 的 `s`/`cs`
标记；检测到后显示可关闭的非阻塞提示，建议提交构建后再预览。不自动提交或远端构建。
检查限时 2 秒，失败不阻止预览；不分析完整依赖图，不判断已提交代码是否部署到服务端。

- 浏览器 `projectid` 参数使用 `.maker-mcp/config.json` 中的真实 `project_id`。
  同一项目有多个本地目录时附带 `checkout` 登记标识；缺少该标识时让用户选择，不猜测目录。
  旧 `project` 链接仍可读取。内部操作继续携带目录级登记标识，由服务端验证 realpath
  与 Maker 绑定，不使用全局当前项目；目录迁移或重绑后需重新添加。
- 项目发布名称为空或仍为 `<game title, required>` 时，显示“目录名（缺少发布配置）”，
  不修改项目配置；此标签是名称缺失时的展示约定，不代表查询过线上发布状态。
  此类项目点击预览时弹窗建议先生成一次测试二维码，并说明直接预览的准备耗时；用户可继续预览或取消。
- 服务仅监听 `127.0.0.1`，校验 Host、Origin 并拒绝跨站请求；PAT 不进入网页。
  只开放固定 CLI 操作，不提供任意 shell 或文件浏览。
- 控制台不生成或校验访问 token，不使用 Cookie 或浏览器会话存储进行授权。
  服务运行时直接打开 `http://127.0.0.1:端口/` 即可选择项目，刷新和新标签无需凭证；
  CLI 链接附带可选的 `projectid` 参数，多副本时附带 `checkout`。页面保持 `no-store`，写操作要求精确同源。
  旧记录中的 token 字段不再使用；旧版服务仍运行时，先用旧版本的 `console stop` 关闭，
  再用新版本 `console open` 启动。Maker PAT 与插件自己的凭证不受影响。
- “项目”页底部提供暗红色“关闭Maker控制台”按钮，二次确认后关闭整个控制台服务。
  有任务、版本更新或文件夹选择进行时拒绝关闭；不删除项目，也不停止独立本地预览。
- 项目登记统一使用 Maker user home 的 `projects.json`；写事务加跨进程锁并原子替换。
  项目目录通过系统原生 realpath 归一；Windows 的 `C:` / `c:` 使用同一登记与预览身份。
  旧的非规范路径登记显示失效；重新添加目录时合并仅盘符大小写不同且绑定相同的登记，
  不移动或删除旧缓存。不同真实目录即使 `project_id` 相同仍分别登记，不将整条路径转小写。
  若旧小写盘符缓存仍有活动或状态不明的预览/验证，新操作保持阻塞；先用旧版停止后再重试，
  不因项目 key 归一而绕过旧会话和项目副本的占用保护。
  旧控制台列表只迁移一次，登记失败不改变 init/clone 结果。
  遗留登记锁不能按时间抢占，确认写入进程已停止后才处理提示的 `.lock` 目录。
- 查询、任务、输出和历史均设上限；退出清理连接、定时器和本实例状态。
  只清理已确认所有权的进程，不按名称终止。生命周期和存储实现分别见
  `src/maker/console/`、`src/maker/projectRegistry.ts`。
- macOS/Linux 的 CLI 进程组守卫是 best-effort；同步阻塞可能延迟父进程退出后的回收。
  Windows 普通预览自动启动控制台，外部 console serve 仅供需要独立于整个 IDE 的场景。
  Runtime 不 detached，强杀清理依赖 Node/libuv Job 行为；实机结果不等于所有宿主或杀软均通过。
  控制台执行的直接 CLI 子进程已覆盖终止测试，辅助进程清理仍需实机验证。
  固定 Runtime 安装器另有清理确认机制，不能据此推断所有 CLI 子进程均已回收。

Windows 正常预览由控制台或 Agent Node 直接持有 Runtime，旧 CIM 仅为显式兼容入口。
最新实测和未覆盖边界见 [启动方式探针](MAKER_WINDOWS_RUNTIME_LAUNCH_PROBE.md) 的最新记录。
历史 breakaway 与强制手动 Host 方案不是当前默认流程。
