# 视频到序列帧：构图与编辑指南

## 官方 Skill 参考结果

只读核对 maker-official-skills/skills/sprite-gen（2026-09-26），未执行生成或修改参考仓库。

1. **先处理首帧构图，不只修改视频提示词。** scripts/prepare_ready_image.py 的 \_compose_to_backdrop 将透明角色放到方形纯色底，主体默认占 60%；config.json 的 ready_layout.content_ratio 可调。当前示例竖图角色较大，挥剑光效超出原画面，后处理不能恢复。建议攻击首帧采用方形或横向画幅，主体及武器约占 50%-60%，右侧给完整攻击弧线留空间。50%-60% 是本项目建议，不是 Skill 对生成成功率的保证。
2. **固定镜头与纯色背景。** prompts/attack.txt 要求静态镜头、居中、纯色底，动作是极快攻击后缓慢收势。不要照搬“瞬间攻击”到所有示例：4 FPS 可能漏掉极短的挥剑峰值。演示建议可辨认的蓄力、挥剑、收势，必要时只提高该动画 FPS。
3. **不是机械照搬 Skill 默认帧率。** config.json 当前是 24 FPS，而 Maker 按产品要求默认 4 FPS、3 秒 12 帧；它是可调抽样参数，不是动作质量保证。现有视频与已保存设置不被自动覆盖。
4. **统一缩放与坐标系。** scripts/helpers/sprite_export.py 的 \_build_frame_entries 先按完整画面统一缩放，再记录裁剪位置；注释明确避免逐帧紧裁后各自缩放导致取整漂移。Maker 保持等尺寸帧和 contain 适配，不默认逐帧紧裁。需要游戏级 trim/pivot 导出时再单独实现契约，不凭空丢掉偏移信息。
5. **半透明特效需要去溢色。** 官方 scripts/helpers/chroma_key.py 使用色差推算透明度并扣除幕布色，能处理被特效包围的背景及半透明混色，不能仅做边缘连通删除。新任务默认使用色差抠图；旧任务未保存模式时仍按旧的连通算法。可在抠图步骤切换。背景必须与角色及特效不同色，同色服装/光效可能被误删；先单帧检查再应用，不承诺恢复真实未知的前景颜色。
6. **贴边提示不是完整性认证。** 抠图后检查原帧四边，多个非透明像素触边时标出风险帧；可能是源视频裁断，也可能是背景残留。先看原视频，不通过缩小已截断图像来伪装修复。提示没有出现也不能证明运动方向、动作质量或所有特效完整，仍需逐帧目视验收。

## 推荐的下一轮攻击视频输入

先把首帧角色缩小、置于纯色宽画布，再用于图生视频。不要仅在已经裁切的视频上扩大输出尺寸。

提示词建议：保持同一蓝银盔甲战士、红围巾和武器，固定全景镜头；角色与整把剑约占画面高度的 55%，四周保留安全留白，向右攻击一侧预留更大的完整动作空间。蓄力、向右挥剑、收势，每个阶段姿势清晰；全部剑尖、挥砍弧线、粒子及拖尾始终在画面内，远离四边。禁止镜头跟随、推近、缩放、画面裁切、出框和额外角色。背景为与角色及攻击特效不同色的均匀纯色，无地面、纹理、阴影、文字或水印。

这是生成构图指导，不会由编辑器自动发起付费生成。旧视频已经缺失的内容保持如实展示；用户要求重新生成时必须走 Maker 真实生成流程并检查新结果。

参考图模式与首帧模式不同：前者允许改变姿势和构图，不能保证保留输入图片的主体比例。要约束攻击构图，应核对生成工具是否支持真正首帧模式，并逐帧检查输出；画布统一标注“来源图”，不把参考关系误称为锁定首帧。

本轮实测（2026-09-26）：仅缩小参考图并增加禁止出框的提示，仍出现剑光越界。改为工具声明的 first_frame 模式与图片角色，结合约 30% 的小主体首帧及紧贴刀刃的短弧动作后，当前攻击样本全 97 帧检查未发现越界。四方向跑步使用同一角色参考图分别生成，不用左右镜像代替生成。这个样本结果不构成所有后续生成的质量保证；正式验收需检查原视频全部帧，不能只检查 4 FPS 抽取结果。

## 编辑与保存

1. 导入视频，创建序列帧卡；新任务默认取前 3 秒、4 FPS，可修改区间与帧率。
2. 抽帧后在右侧预览取背景色，统一抠图；检查重复帧并确认移除。
3. 左侧点帧，右侧点击“编辑当前帧”；单图编辑可应用当前帧，或将操作批量应用全部帧。
4. 整理页可拖动排序、倒序、隔帧精简，撤销/重做帧编辑。至少保留一帧。
5. 统一输出尺寸后保存到画布，再创建动画卡。已存在动画卡保留创建时的快照，不随重新编辑自动替换。

单帧编辑只修改临时草稿，帧集保存成功才替换节点。批量取消与失败不覆盖原帧；关闭时放弃草稿不改已保存结果。
