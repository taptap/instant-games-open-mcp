# Maker 控制台 Git 拉取设计

> 日期：2026-09-22
> 状态：已实现。入口为 Git 页「拉取远端代码」，逻辑在 `src/maker/console/gitPull.ts`。
> 用途：后续实现必须遵守本文，不得自行扩大合并能力

## 1. 结论

Git 页增加「拉取远端代码」。Maker 只使用 `main`。当前不在 `main` 时只在页面提示，不切换分支。

在 `main` 上先 `git fetch origin`，再按文件路径判断：

- 远端有新提交，本地没有自己的提交，本地改动和远端要更新的文件不重叠：`git merge --ff-only origin/main`。远端代码进来，本地未提交修改留在原地。
- 本地已有自己的提交：不改写历史，不 rebase。页面说明后交给 AI。文件相交时仍弹出可复制提示词。
- 同一文件两边都改过：不拉取，不 stash，不合并内容。弹出对话框，给出可复制给 AI 的提示词。

不自动提交、推送或构建。不使用 reset、checkout、stash 或 autostash。

## 2. 同一文件两边都改过

触发条件是路径相交，包含重命名的新旧路径，以及远端将要新增、但本地已有同名未跟踪文件的路径。

两条路径都算：

- 只落后远端，本地未提交修改碰到了远端要更新的文件。
- 双方都有提交，本地提交和远端提交改到了同一批文件。工作区是否干净不影响这条：文件已经相交，就不再 rebase。

检测到后：

1. 不执行 merge、rebase、stash。
2. 游戏文件保持原样。`git fetch` 只更新了 `.git` 里的远端引用。
3. 立刻弹出对话框。关闭对话框不重试拉取。
4. 同一结果保留在 Git 页，避免用户关掉弹窗后找不到提示词。
5. 切换项目时关闭弹窗并清除上一个项目的提示词。

对话框复用控制台现有 `<dialog>`，不使用会执行 Git 的确认框。标题说明发生了什么，正文只放短说明和提示词。按钮是「复制给 AI」和「关闭」。复制失败时选中文本，提示手动复制。

提示词使用下面的固定模板。花括号由服务端填入，不接受浏览器传入的说明文字。文件列表最多 30 条，超出时写明总数。路径过长时截断单条路径，不截断项目根路径。

```text
Maker 控制台无法安全拉取，因为下面的文件在本地和远端都有改动。控制台没有修改这些文件，没有合并，也没有 stash。

项目：{projectPath}
分支：main
本地未推送提交：{aheadCount}
远端新提交：{behindCount}
本地未提交修改：{localChangeCount} 个
冲突文件：
{conflictFiles}

请先读取这些文件的本地内容和远端 main 的对应版本，用普通话说明两边分别改了什么。不要执行 pull、rebase、stash、reset 或 checkout。给出保留方案后，等我确认再改文件。Maker 只使用 main，不要新建分支。
```

`conflictFiles` 每行一个路径。本地未提交修改和本地提交都可能造成相交，提示词不需要区分 Git 术语；AI 读到项目路径后自行查看 `git status` 和差异。

页面短说明：

```text
这些文件两边都改过，控制台没有更新代码。请把提示词复制给 AI。
```

## 3. 其它停止情况

不在 `main`、正在预览、已有未完成的 Git 操作、远端不可用，只在 Git 页显示一句原因，不弹这个复制框。这些情况没有同一份「两边都改过」的文件列表，硬弹同一提示词会让 AI 误判。

双方都有提交但工作区不干净、文件又不相交：同样不弹冲突框，页面说明本地还有未提交修改，请让 AI 处理。不自动 stash。

## 4. 安全边界

- 浏览器不能传入目录、远端、分支、Git 参数、凭证或提示词正文。
- 提示词不包含文件差异、PAT、带凭证的 Git 地址。
- 弹窗关闭、复制失败、项目切换都不会启动第二次合并。
- 不新增 MCP tool。
