# 常见问题与兼容冲突

[返回共享画布入口](../README.md)

遇到行为不一致或准备修改跨端接入时，按场景查阅；不要求每次开发通读。
这里只沉淀已验证的问题和容易误用的接入边界，不把推测写成限制。

## 共享代码合入了，但 Web 没变化

**场景：** 修改 Maker MCP 中的共享实现，期待 Web 随 main 合并立即更新。

**原因与后果：** Web 消费生成到自己仓库里的快照；源码合并不等于消费端更新。
直接修改 Web 的生成产物又会在下次导入时被覆盖，形成“修好了又回来”的问题。

**做法：** 先核对消费端记录的来源 revision 和实际加载产物。公共逻辑改共享源码，
再通过消费端原有导入流程更新；宿主差异改宿主源码。无需为此要求两端总是同步发布。
详见[构建与验证](本地与Web接入.md#构建与验证)。

## 界面可以选，提交却提示参数不支持

**场景：** 共享界面增加模型、视频时长等选项，宿主或后端仍使用旧枚举、旧范围。

**已确认例子：** 核对 #933 时，共享画布提供 2.0 模型最长 15 秒、2.5 模型最长 30 秒，
当时 Web 提交校验仍限制 4–8 秒，超过范围会在提交前被拒绝。这里记录的是当时的接口差异，
不是要求以后继续保留这些取值。

**做法：** 同时核对界面、宿主与实际服务的参数范围。服务尚未接通时只展示已支持选项；
不要仅删除校验来让请求通过。根据具体链路判断是否已经提交，不能把“报错”统一当作未执行。
详见[视频服务](本地与Web接入.md#视频服务)及[任务恢复](本地与Web接入.md#保存来源版本与任务恢复)。

## 把可显示的地址当作可保存、可跨端使用的素材引用

**场景：** 页面已经能展示图片或视频，就把 Blob URL、本机绝对路径或带鉴权的访问地址
写入模板、画布文档，或直接交给另一端。

**已确认边界：** 显示地址与持久化素材身份不是同一件事。本地与远端的项目、路径和授权
分别由宿主解释；当前页面能读到，不代表刷新、换项目或另一端也能读取。

**做法：** 文档保存宿主认可的素材引用，读取时再解析访问地址。跨端导入映射到目标端返回的引用；
导出只按真实交付结果报告保存路径，不把浏览器下载伪装为项目落盘。
详见[素材读取与交付](本地与Web接入.md#素材读取与交付)。

## 打开功能开关，就认为整条流程已经接入

**场景：** 打开模板、识图或 UI 编辑器入口，以为服务、保存、权限与后续编辑能力会自动可用。

**已确认边界：** features 控制页面入口，不提供服务或权限。尤其 uiEditor 当前控制导出后的组装交接，
并不意味着独立 UI 编辑器已经包含在共享包中。关闭入口也不会自动禁用同名 Agent 操作。

**做法：** 沿实际功能链路补齐所需宿主能力，保留未接通原因；允许分阶段接入。
只为当前要开放的功能补齐依赖，不顺带建设通用框架。
详见[平台与能力开关](本地与Web接入.md#平台与能力开关)。

## 新旧说明冲突，难以判断当前行为

**场景：** 一个章节保留旧行为，另一个章节追加新能力，后续开发只读到了其中一处。

**已确认例子：** 原 README 同时保留“多页精灵表仅预览第一页”和后加的“支持多图集预览”。
此次核对源码后已统一为支持多图集预览，同时保留不能重新导出、编辑或打包的边界。

**做法：** 结合当前源码、直接调用方和相关变更确认语义，更新原说明并清理重复表述；
不要只在文末再追加一条，也不要为迎合旧文档回退正确实现。
当前规则见[多图集预览](画布功能与业务规则.md#多图集预览)。
