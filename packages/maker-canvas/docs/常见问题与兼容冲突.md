## Web 同步共享画布时，视频时长选项与提交校验可能不一致

### 影响哪一端、是否实际发生

这是 2026-11-10 审核 #933 时发现的 **Web 下次同步共享代码的兼容风险**，
不是本地 Maker MCP 运行报错，也不是已在线上发生的 Web 故障。
审核时 Web 的共享画布快照尚未包含 #933；没有用真实付费生成验证这一组合。

触发条件是：Web 导入 #933 的共享界面，同时继续保留原有 4–8 秒的提交校验。
这样选超过 8 秒才会在 Web 提交前被拒绝；当前旧界面与旧校验配套时，不存在这个新增选项冲突。

### 为什么本地原来只提供短视频

产品负责人在 2026-11-10 说明：**生成视频费用高，本地视频主要用于序列帧动画，
通常 4–5 秒就足够；时长增加会带来更多待抽取和处理的画面，后续抽帧更不方便。**
所以短时长选项服务于成本控制和序列帧制作流程，不能只当作待放开的技术限制。

4–8 秒是当时界面允许选择的范围，4–5 秒是该制作场景通常足够的时长，二者不能混为一谈。
模型能够生成更长视频，不等于产品默认就应该提供更长时长；Web 是否沿用同样策略，也要结合其实际用途判断。

### 证据从哪里来

- **本地与共享界面的历史行为：** #933 之前，
  [generationUi.ts（ad53031e）](https://github.com/taptap/instant-games-open-mcp/blob/ad53031e/packages/maker-canvas/src/browser/generationUi.ts#L2580)
  的时长选项为 4、5、6、7、8，默认 4 秒，超过 5 秒标红。
- **共享界面变化：** #933 合入的
  [generationUi.ts（4e9e628）](https://github.com/taptap/instant-games-open-mcp/blob/4e9e628/packages/maker-canvas/src/browser/generationUi.ts#L2596)
  将 2.0 模型选项扩大到 4–15 秒、2.5 扩大到 4–30 秒；该选项代码没有单独限制 Web。
- **Web 侧校验：** 审核的 Web 仓库版本为 `9c6e4b9d`。
  `packages/shared/src/canvasGeneration.ts` 中 `CANVAS_VIDEO_MIN_DURATION/MAX_DURATION` 为 4 和 8；
  `apps/web/src/features/canvas/canvas-generation.ts` 的 `prepareVideo` 在创建提交请求前检查这个范围。
  对应 `canvas-generation.test.ts` 已有 `duration: 9` 用例，断言 `not_executed` 且未调用 submit；
  此次审查运行的相关测试通过。这验证了 Web 拒绝路径，不等于真实生成或同步后的浏览器联调。
- **Web 尚未同步：** 当时 `apps/web/src/features/canvas/vendor/source.json` 记录的共享版本为
  `04d0d1fb`，不含 #933。以上版本和取值是审查证据，不代表以后必须保持不变。

### 后续开发应该怎么处理

先确认此次功能面向短序列帧还是其他视频用途，再决定界面允许范围、默认值和费用提示，
并让界面、Web 提交校验与实际服务能够配套工作。
**不能为了消除校验报错直接放宽到模型上限，也不能把 4–5 秒常用时长擅自改成新的硬上限。**
若延续短序列帧用途，应保留成本和抽帧便利性的设计意图；若明确需要长视频，再做相应的产品与接口调整。

详见[视频服务](本地与Web接入.md#视频服务)。本次文档整理未修改视频选项或提交校验。

## 共享文档同时保留了两种相反的多图集预览说明

**影响范围与性质：** 这是共享包文档的问题，会影响本地和 Web 开发者理解功能边界；
实际检查发现的是说明矛盾，没有证据表明因此发生过运行故障或有人回退了正确代码。

**原因与证据：**
[整理前的 README（5697ab5e）](https://github.com/taptap/instant-games-open-mcp/blob/5697ab5e/packages/maker-canvas/README.md)
在“图生精灵”章节仍写“多页精灵表仅预览第一页”，又在文末“精灵多图集预览”章节补充支持多图集。
新能力说明被追加到另一处，原说明没有同步更新，导致读到不同章节的人会得到不同结论。
核对 [spriteMirror.ts](../src/features/spriteMirror.ts) 的 relatedMultiPacks 合并逻辑及
[animation.ts](../src/browser/animation.ts) 的 atlasPath 读取后，确认实现已支持多图集预览。

**处理结果：** 此次拆分已合并为一处说明，保留多图集预览与导出、编辑能力之间的区别。
当前规则见[多图集预览](画布功能与业务规则.md#多图集预览)。
以后修改已有行为时更新原说明，不只在文末追加一条；先核对实现再处理冲突，不按过期说明改回代码。

## 后续怎么记录

遇到有复用价值的问题，说明影响本地、Web 还是共享层，区分实测故障与代码审查风险，
写清触发条件、原因和处理依据；产品取舍说明为什么，不把现有参数一律当作缺陷。
证据来自代码、测试、运行记录或用户说明时如实标明，尚未查明的原因不要自行补全。
不用固定模板或每次任务都记录；普通 Git 冲突和一次性故障留在任务或 PR 中。
修复后更新原条目，保留仍有价值的原因，删除失效的临时绕法，不积累流水账。
