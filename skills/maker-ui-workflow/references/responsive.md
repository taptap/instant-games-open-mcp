# 多分辨率 UI 生成与复核

本说明由 Maker 内置 UI 组装、Bbox 工作流、Lua 转 JSON 三条入口共用。
只使用目标项目 UrhoX 已有属性；引擎及其 Skill 不在修改范围。

## 布局与单位

- 先区分全屏页面、弹层和独立组件。全屏根用 `width/height: "100%"`；独立组件保持自身尺寸，
  居中和贴边由使用它的父容器负责。不能把所有 Panel 都改成全屏。
- 沿用项目 `UI.Init` 的实际缩放策略。`UI.Scale.DEFAULT` 是 DPR 与小屏密度适配，
  不会自动把高清设计稿像素换成合理的逻辑尺寸。先确定逻辑参考宽高，再统一换算 Bbox、字号、间距。
  已有 Lua 约束已经是逻辑单位时不再缩放；接入代码只有用户要求接入/修复时才修改。
- 大厅左右、上下按钮按用途和已有父子分组锚定到安全内容区；按钮内的图标、文字跟随按钮。
  不把“离屏幕哪边近”当成确定的业务意图，不拆散一组控件。
- 背景放安全区外，四边 0，按需求选 `cover`（可裁切）或 `contain`（可留白）。
  `SafeAreaView` 默认通过 padding 避让；绝对定位控件放在它的内部普通布局容器里，
  不假定直接给绝对定位节点套一层 padding 就能避让。Tap 胶囊需要时用 `nativeMenuInset: true`。
- 居中面板优先用父级 flex 居中；固定尺寸节点可用 50% 定位加负半尺寸 margin。`maxWidth` 不会缩放内部固定坐标，
  内部应一起改为百分比或 flex。图片可用 `aspectRatio` 从一边推导另一边，避免同时锁死宽高。
- 列表、背包格子、卡片等重复内容由生成该 UI 的 AI 按场景安排。通常让列表容器随可用空间伸缩，
  单项保持设计稿中的逻辑尺寸，不把单项 `flexGrow` 成填满剩余空间。内容超出时滚动或换行，
  不把全部内容压进一屏。排行榜行、文本列表等确需横向铺满的内容可以伸缩，不套用同一套尺寸。
  动态数量、排序和数据仍留在 Lua；预览中的样例项不代表真实数据。
- 窄屏文字要检查换行、字号、内容溢出；保留 Label，不把文字烘焙成图片。
  仅在用户需要换列数、隐藏区域等布局切换时补 Lua；不发明 JSON 媒体查询或断点协议。

## 组装输入

`layout.json` 或含 `bbox` 的 `assembly.json` 可增加 `adaptation`：

```json
{
  "adaptation": {
    "mode": "screen",
    "logicalShortSide": 720,
    "safeArea": true,
    "nativeMenuInset": true,
    "nodes": {
      "E001": {
        "left": null,
        "top": null,
        "right": 24,
        "bottom": 24,
        "width": 120,
        "height": 48,
        "aspectRatio": null,
        "marginLeft": null,
        "marginRight": null,
        "marginTop": null,
        "marginBottom": null
      }
    }
  }
}
```

- `mode` 为 `screen` 或 `component`。`component` 只做单位换算和显式节点约束，不套全屏或安全区。
- `logicalShortSide` 为设计稿短边对应的逻辑长度；省略则不换算。720 只是画布自动组装的初始基准，
  不是所有项目的强制尺寸。项目已有基准时以项目为准。
- `nodes` 按现有元素 ID 覆盖最终节点属性，数值已是逻辑单位；`null` 删除自动产生的属性。
  支持四边、宽高、最小/最大尺寸、padding/margin、字体尺寸、边框尺寸、flex、`aspectRatio`、
  `backgroundFit` 和 `overflow`。不允许通过此处换 ID、图片绑定、类型或 children。
- 原 Bbox 与纠偏记录仍用设计稿像素，不能因适配覆写原坐标。改变父子分组用现有 layout 层级，
  已有交付用 `ui inspect / patch` 修改并检查 revision，不重建覆盖用户修改。
- 未传 `adaptation` 的历史脚本输入保持固定布局。新全屏 UI 应显式传入此配置。

画布自动交付使用 screen、短边 720 和安全区：背景铺满；顶层内容按原稿位置初拟锚点，
原有父子分组保持不变。为面板显式提供宽高、最大尺寸或比例覆盖时，内部位置/尺寸按原稿比例跟随父级。
跟随只作用于该面板内部坐标。列表项、卡片等需要保持自身尺寸的节点，应在 `adaptation.nodes` 中
显式保留宽高，不能依赖名称自动识别，也不能把所有子节点无差别转成百分比。
字号不会随面板无限缩小；拥挤内容需调整 flex、换行或滚动，而非盲目整体缩小。

`assembly-map.json.adaptation` 记录逻辑参考尺寸、`inferred` 元素和待复核状态。
自动锚点只是初稿，已有显式节点覆盖也不等于验收通过。最终 JSON 仅含引擎已有节点属性，
不写入 `adaptation`；它是组装输入和记录，不是引擎新协议。

调整具体边距、伸缩和锚点时读取[排版参数](layout.md)，只使用其中列出的字段。

## 编辑器验收

编辑器连接后，优先用同包 CLI 的 `ui layout` 查询实际布局、`ui preview` 导出 PNG；
通过 `--device iphone18|ipadpro`、`--orientation` 或 `--width/--height` 切换模拟视口。
先查 `ui capabilities` 获取参数。CLI 只渲染保存版本，不动草稿；仍须查看 PNG，不能只凭坐标验收。
浏览器用于首次连接、视觉对照和拖动/缩放等交互验证，不用反复点击设备下拉框读取坐标。

1. 对照参考图检查分组、层级和内容。基准对位时在自定义设备中使用逻辑参考宽高、DPR=1、UI 缩放=1。
2. 切换 720p、1080p、iPhone 18 Pro、iPad Pro，检查贴边、居中、背景比例、文字溢出；
   按项目支持范围切换横竖屏，必要时自定义 4:3 / 21:9。720p、1080p、2K、4K 预设的模拟 DPR
   分别为 1、1.5、2、3，逻辑画幅相同，用于检查不同像素密度，不代表更大逻辑视口；
   检查更大桌面时用自定义分辨率及实际 DPR，不能仅凭物理分辨率推断 DPR。
3. 编辑器默认模拟 `UI.Scale.DEFAULT`；项目用其他策略时，在自定义设备中填入对应缩放值。
   页面按设备逻辑视口重新布局；固定像素根仍然保持固定大小，不能用整体缩放掩盖它的缺陷。
4. 安全区预设是可编辑的模拟值，宿主窗口和 Tap 胶囊并不由手机型号唯一决定。
   在自定义分辨率中填写物理像素边距与胶囊底边位置，核对 `SafeAreaView` 是否实际避让。
5. 拖动/缩放后检查 right/bottom、百分比和 aspectRatio 是否保留，保存重开后再换设备。
   设备切换本身不修改 JSON。
6. 静态检查、编辑器预览、引擎运行分开报告；未运行真机不能宣称全面适配通过。
