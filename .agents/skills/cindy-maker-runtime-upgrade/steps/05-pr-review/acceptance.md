# 05 验收

本步按实际范围区分“草稿已提交”“审核待外部处理”“可合并”“已合并”，不强求每轮
都完成发布。查状态可交付准确状态报告；完整审核跟进必须继续完成已授权且可执行的工作。

- [ ] 动作符合授权；官方仓/base/head/fork/PR 状态与完整 SHA 正确，提交和推送均使用
      本轮新建分支，未直接提交或推送 main，未沿用已合并 PR。
- [ ] 当前仓库门禁满足，版本/最终包/正文一致，DCO 来自 GitHub 实际 PR commits/check。
- [ ] review、线程、普通评论及已知事项核对完整；每条有依据与处置，缺陷/验证缺口/异议/外部等待没有混淆。
- [ ] 确认缺陷修复验证完成，新增保护回填清单和配方；未完成则保持未就绪，未删功能或弱化门禁换绿灯。
- [ ] 受影响路径证据对应最终产物，按影响重测/打包/安装；复用旧证据有完整差异依据。
- [ ] PR 说明和回复准确，不实归因已更正；Resolve 不掩盖风险，outdated/线程为零未被当作全部解决。
- [ ] 最新 head 的必需检查、有效 review、冲突和未结事项已复核；运行中的审核及最小下一步已报告，未提前宣称只差 approval 或市场已发布。

仍有未解决缺陷、必需验收缺口或检查未通过时，不标“可合并”。用户允许提前提 PR
则保留 Draft 和真实未完成项。缺有效 approval 时交付“待批准”；实际边界决定/平台批准
未就绪时单列等待及范围，不能靠关闭线程或改勾选绕过。
已有合并授权也须在门禁满足后才能执行；没有授权则交付审核结论。
