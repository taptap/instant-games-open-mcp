# 04 验收

- [ ] 包含本次实际修改，未把 HEAD 旧归档当工作树新包；包内版本、完整 vendor/adapter/法律文件校验通过。
- [ ] 最终 .cindy SHA-256、包内 maker.js 哈希、recipe 与测试版本对应，原始包/补丁包没有混淆。
- [ ] 本轮授权包含安装时已取得成功回执，并核对实例/版本/来源与文件一致；没有将取消视为成功。
- [ ] 通过已安装插件调用得到目标 Runtime；同名 standalone/旧 Console 未混入证据。
- [ ] 已按差异完成 Host 基础调用、设置/画布/UI 编辑器/进程等集成验证，记录实际宿主版本及渠道。
- [ ] 第三步及本步所需场景均通过；未改路径引用有效历史证据时有依据，没有以旧版实测代替新包。
- [ ] 未覆盖平台、付费/生产故障等边界准确说明；代码问题、验证缺口、边界决定和平台等待分开。
- [ ] 更新清单/历史来源及正式交付说明，脱敏日志与图像证据存仓库外，未带入真实游戏/账号数据。
- [ ] 按用户已授权范围交付；任务包含提交/PR 时，已交接当前版本、证据与缺口到 [第五步](../05-pr-review/run.md)，PR 是否就绪按该步验收判断。

只要求本地适配或打包时，安装项标“范围未包含”，明确交付边界，不伪称通过 D 验收；
任务要求完整升级验收而仍缺安装/实际场景时，保持“待验收”，给出具体下一步。
各阶段验收是 Agent 自检，不是每阶段都要求用户人工确认。
