# 长任务等待、图片传输与超时未知态

维护于 2026-11-05。检查 H7/H8/T3 时读取；用于插件层适配和升级防回归，
不要求修改 Maker Runtime 或 Cindy 客户端，也不新增远端重试器。
本文件记录问题与处理契约，不是本轮修复已完成或已发布的证明。

## 先分清三个问题

| 现象                                           | 原因与处理                                                          | 检查项 |
| ---------------------------------------------- | ------------------------------------------------------------------- | ------ |
| 高质量生图等调用超过两分钟、期间没有进度而超时 | Node 静默窗口到期；补齐插件内外两层等待通知，保留总期限             | H7     |
| 大参考图／首尾双图请求远端根本没收到           | 子进程 stdin 单帧过大被 Host 丢弃；按原始字节分块传输，延长等待无效 | H8     |
| 超时后只报普通失败，用户再次生成可能重复扣费   | 等待结束不代表远端未执行；最终保留 unknown，禁止自动重送            | T3     |

只增加等待时间、只分块或只补错误提示，不能互相替代。

## H7：两层等待与总期限

先从实际执行电脑的版本、构建来源或发行文件核对 Host 契约，不能拿最新 main
替代旧宿主。本次核对的 Cindy 0.1.125 发行文件中：

- `cindy.node.request.timeoutMs` 上限 120000；声明 `maxTotalMs` 后，
  它是静默窗口。合法 stdout JSON-RPC 消息或 stderr 活动可续期，
  仍受 `maxTotalMs` 约束（上限 900000，即 15 分钟）。
- 外层工具默认窗口 330 秒；`tool-progress` 按真实 `callId` 续期，
  总期限上限 30 分钟，显式短期限不一定允许续期。
- Agent MCP 调用另有自身期限；原报告的 Codex 环境为 600 秒，
  不是所有环境的固定值，不能承诺通过插件通知无限等待。

插件适配保持在已有 `main.js`、`node/mcp-root-router.cjs` 等转接链：

1. 保留 `timeoutMs:120000` 与 `maxTotalMs:900000` 的配合；
   超过 120000 的 timeoutMs 不会得到更长合法等待。
2. Node 内层对在途长任务发合法活动通知（例如每 30 秒），经现有
   `writeHost` 通道到宿主；进度 token 本身不会产生通知。
   注意 `maker-mcp.cjs` 已转接 stdio，不直接向被替换的 stdout 乱写文本。
3. 外层等待时发 `cindy.send({type:'tool-progress',callId})`，
   `callId` 使用当前宿主下发值；只加外层不能续 Node 内层，反之亦然。
4. 复用已有机制，按各自 JSON-RPC ID／callId 隔离并发；成功、失败、
   已支持的取消路径及总期限停止时清理。通知有独立的最长生命周期，
   不能在请求到期后无限发送，也不把通知失败变成重送生成请求。

通知只表示“本地仍在等待”，不能伪造远端百分比、证明请求已送达或已扣费。
同 worker 活动可能为其他长请求续期，每项请求仍须保留绝对截止时间。
不改变短状态查询、内部 tools/list 的 115 秒回收余量及账号已有进度机制。
取消接线不足需列缺口；停止本地等待不等于取消远端生成。

## H8：子进程 stdin 分块

`PNG → Base64 data URL → JSON-RPC → 通道 Base64` 会再次放大数据。
报告及本次核对的发行文件中，单帧通道上限为 1,048,576 个 Base64 字符；
报告重建的双图请求为 1,534,225 bytes，编码后 2,045,636 字符，原链路被丢弃。
这个限制不同于 Maker 的单张图片限制，也不同于主 Node 请求参数上限。

核对 `child-process-adapter.cjs` 的 `createDeferredChild`：
把原来整段 `nextHandle.stdin.write(chunk)` 改为有序发送 Buffer 子段。
报告方案每段 `64 * 1024` 原始字节，Base64 后最多 87,384 字符，低于该限额。
按目标宿主再次核对限额；已有等价分块机制不重复叠加。

不按字符串切片后重新编码，不给分块添加换行，不重复 JSON-RPC ID，
完整字节流仍是一笔请求。保留异步句柄前的 stdin/PAT 缓存、EOF 顺序、
退出和错误处理；这不是上传大文件的新通道，也不放宽其他输入／输出限额。

## T3：超时后的结果不能丢状态

参考 [官方插件 PR #159](https://github.com/makecindy/cindy-official-plugins/pull/159)
的实际 diff：`nodeRequest` 保留宿主 `errorCode`，已派发长任务遇到
`TIMEOUT` 时最终为 `execution_state:unknown`、`automatic_retry:false`，
提示核对远端任务、产物和用量。不伪造 task_id，不触发身份恢复重送。
发送前拒绝仍为 `not_executed`，短查询不扩大为付费执行未知态。

截至 2026-11-05 查询，该 PR 是未合并草稿；后续以实际状态和正式代码为准，
不能仅因 PR 存在就认定已有保护。它不延长等待时间，也不修复大请求丢包。

## 验证与证据

第二步对本轮真实 adapter/router/main 实现做定向回归，优先模拟延迟与时钟：

- 210 秒静默后成功，去掉内层通知的对照会到 120 秒期限；
  400 秒场景覆盖外层窗口，测试调用方自身期限须足够。结果属于原请求，仅派发一次。
- 并发完成不串线，正常／异常／已有取消路径清理；永不返回仍受总期限约束。
- 超时最终 unknown、不伪造任务编号，调用计数为一，身份恢复不重送。
- 大请求在通道限额前后、双图大小、UTF-8 跨块、多次 write、EOF 和并发子进程
  隔离均保持字节一致；每块满足真实 Host parser 的限制，分块不会多次生成。

第四步针对受影响路径，在实际 Cindy、确切已安装插件实例核对长等待及传输链。
优先使用不联网的受控延迟／字节接收端验证，不能把理想 mock 当完整 Host 链；
真实付费生成只在已有明确授权时执行，不为验收自动扣费。
记录版本／渠道、包及 adapter 哈希、实际耗时、单次派发及最终结果；
历史证据仅在相应路径未变且有完整差异依据时复用，未测项如实交接。
