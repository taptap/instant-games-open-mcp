# Cindy Maker Runtime 升级工作流

本目录随 Maker MCP 源码仓库迁移，macOS、Windows 使用同一流程。
这里只放路线；不要一次读取整个目录。操作和验收分开加载，上一步验收通过后才进入下一步。

## 使用

用户说“按这个工作流升级 Cindy Maker Runtime”即可开始。确定 Maker 源码仓库、
Cindy 官方插件仓库和目标版本；能从当前目录、现有配置与产物确定的，不重复询问。
本目录不依赖原电脑的聊天数据库、绝对路径或全局 Skill 安装。

| 顺序                             | 本步操作时读取                                                 | 操作完成后读取                                  | 交付给下一步                                           |
| -------------------------------- | -------------------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------ |
| 1. 准备版本和替换候选包          | [01 操作](steps/01-source/run.md)                              | [01 验收](steps/01-source/acceptance.md)        | 来源、版本、构建/包哈希、原始包及候选目录              |
| 2. 逐项兼容审核并完成替换        | [02 操作](steps/02-compatibility/run.md)，按其中顺序逐组读清单 | [02 验收](steps/02-compatibility/acceptance.md) | 每项结论、最终补丁配方、vendor、必要适配和自动回归结果 |
| 3. 本机 CLI 与真实游戏验证       | [03 操作](steps/03-local-cli/run.md)                           | [03 验收](steps/03-local-cli/acceptance.md)     | 精确入口、实际进程/游戏/画面/报告证据                  |
| 4. 打包和 Cindy 安装验收         | [04 操作](steps/04-delivery/run.md)                            | [04 验收](steps/04-delivery/acceptance.md)      | 可核对的安装包、宿主证据、交付结论                     |
| 5. PR 审核处理（任务包含 PR 时） | [05 操作](steps/05-pr-review/run.md)                           | [05 验收](steps/05-pr-review/acceptance.md)     | 当前提交对应的审核处置、证据和剩余门禁                 |

仅获准提前提 Draft PR 时，可在前面验收未完成时先进入第五步建草稿；保留未通过状态，
继续补齐前面步骤，不将草稿创建视为升级完成。

## 执行约定

- 每轮升级在修改插件前，先从已核对的最新官方 main 新开本轮分支；恢复同一轮任务时沿用
  该分支。不得直接在 main 提交或推送，也不得复用已合并 PR 的旧分支。保留现有改动；
  脏树不能安全切换时用独立工作树。提交前再次核对当前分支及其对应的 PR。
- 首步建立仓库外的本次记录，使用 [交接模板](templates/run-record.md)。每步只携带来源摘要、
  当前检查组结果、下一步及证据路径；原始日志留盘，切步无需重读之前全部材料。
- 全部兼容项都要核对；未变行为可引用适用证据，不逐项重抄历史、重写测试或重复执行。
  不适用项注明原因；测试范围随本轮差异确定，单项失败只阻止依赖它的验收。
- 两分钟以上静默等待、大图片子进程传输和超时后未知状态，按第二步 H7/H8/T3 核对；
  仅提高到 120 秒或沿用旧版测试不能算问题已修复，处理依据见该组链接的专题。
- 每个阶段、每个兼容组均由 Agent 按验收文档自行判定；不要求用户逐步点击批准。
  缺必要证据时写清未通过项，完成可独立继续的检查；不得把该阶段标成通过后推进依赖它的步骤。
- 本次授权决定执行范围。升级不自动授权 commit、push、PR、合并、发布、付费生成、
  生产云端写入或修改其他 Agent 配置。已有明确授权直接沿用；工具的实际确认门照常处理。
- 遵守两仓当前 AGENTS.md。保留用户已有修改，不顺带重构。原始包、候选包和最终安装包
  分开记录；版本名、测试全绿、旧版实测均不能代替目标产物的证据。
- 历史保护先保留，再证明上游等价替代；以已确认的新版功能为准，不恢复被替换的旧方案。
  已确认范围沿用，不为普通适配反复提问；真实功能取舍或权限边界变化才交用户决定。

恢复任务时先读本入口和本次记录，核对工作树/产物是否变化，再读当前步骤及其验收文档。
修改最终 bundle 后，相关自动回归、本机验证和安装包一致性证据需要更新。
